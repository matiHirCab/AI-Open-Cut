# Artifact delivery

The bridge advertises `artifact_resources_v2`. This is version 2 of the artifact **content** policy: completed job polling returns text metadata plus an MCP resource link by default. It never opens or encodes the output file during ordinary polling. The optional `artifactResource` field also appears in `opencut://jobs/{jobId}` JSON. Existing structured `artifact`, `speechPreview`, results and errors remain available.

Clients relying on legacy inline PNG/WAV blocks must migrate to `job_get_status({ jobId, includeBinary: true })`. False or omission returns metadata only. MP4 range/export output stays linked even with true. Call MCP `resources/read` with `artifactResource.uri` to retrieve PNG, WAV or MP4 as a blob on demand. No path or speech token is accepted as a resource address; display names are fixed labels. Size is supplied for render artifacts, omitted when unknown for speech.

URIs are `opencut://jobs/{opaque UUID}/artifact`. The MCP SDK normalizes URL spelling (scheme/host case and plain or percent-encoded dot segments); equivalent URLs select the same canonical lowercase UUID resource. Queries, fragments, encoded UUID bytes, invalid IDs and remaining suffixes are rejected. Resources are scoped to the owning bridge process registry. The existing authenticated HTTP MCP endpoint and its host/origin/body restrictions protect reads exactly as they protect tools. Authorized clients of the same bridge retain its existing shared job access; the active project selection is not an access-control list. Foreign registries, eviction, expiry and restart return `JOB_NOT_FOUND`. File retrieval never changes project selection, revision/history, or starts rendering or synthesis.

Descriptors indicate retained metadata, not guaranteed current file availability. Their expiration is job retention, bounded by speech-preview expiration. Consumed, discarded or expired speech returns `GENERATED_ARTIFACT_NOT_FOUND`. Missing/unreadable files, invalid paths, symlinks or unsupported output access return safe `VALIDATION_FAILED`; MCP resource RPC errors contain the stable code and safe message without filesystem details. Polling remains available for a retained job after output deletion or speech disposal.

Render paths stay relative under the corresponding project's previews directory or the configured exports root. Speech output stays under configured generated-media roots. Traversal, absolute/drive/UNC/network paths, directories and symlink escapes are rejected. The configured root and its descendants cannot be symlinks; trusted parent aliases above the root are resolved to a canonical confinement anchor. These are application I/O checks; authorized local filesystem writers remain trusted. Export overwrite retains existing path-backed semantics, so a link can observe the current file at the recorded export path.

The existing speechPreview.token and generatedArtifact.token fields are intentional commit handles; they are never copied into resource URIs, names or errors. No new network resource, headless request, project schema, renderer semantics, timing, ordering, undo/redo or migration rule is introduced. Canonical behavior and examples live in contracts/artifact-delivery-v2.json; structural MCP discovery remains an additive extension of mcp-surface-v1.json.


Preview producers reserve a count slot until their work settles, including cancelled work. Required eviction finishes before replacement production. If disposal fails, its file remains owned and charged; replacement previews fail with retryable `JOB_REGISTRY_FULL` until safe cleanup succeeds. Nonpreview jobs retain their ordinary admission policy. An already-produced oversized or cancelled file can remain cleanup debt when filesystem deletion fails; this is not successful retained output and does not permit further preview production.

Graceful close settles producers and attempts native confined cleanup. Cleanup failure returns a safe `VALIDATION_FAILED` error and preserves ownership for a subsequent close attempt; admission stays closed. Cleanup runs privately through the existing headless binary and uses native directory/file handles to prevent ancestor replacement from redirecting deletion. It adds no public MCP/headless operation or runtime role.
