# Scoped alpha and luma track mattes

Schema34 adds `matte: {sourceId, channel}` and `matteOnly` to eligible visual leaves. The canonical contract is [track-mattes-v1.json](../contracts/track-mattes-v1.json). Text, solid color, rectangle, shape, SVG, grid and managed image/video leaves may provide or receive a matte. Audio, captions, groups, repeaters, component instances, template instances and transitions accept only default stored fields. Core resolves managed media eligibility and scoped dependencies; transport schemas do not infer assets or build a second graph.

Stored eligible `matte` is optional and non-null. Missing fields mean no reference and ordinary drawing; defaults serialize by omission. Ineligible stored records require absent matte and optional false-only matteOnly. Existing update-item omission preserves a field, an object replaces a reference, `matte:null` clears it, and `matteOnly:false` restores direct drawing. Explicit matteOnly null always rejects. Existing operations, protocol1 and draft envelope2 remain unchanged.

```json
{
  "projectId": "project-id",
  "expectedRevision": 2,
  "itemId": "recipient-id",
  "matte": {"sourceId": "provider-id", "channel": "luma"},
  "matteOnly": false
}
```

Submit this input to `timeline_update_item`; use `operation:"update_item"` inside existing batch or draft operations. Source IDs are literal canonical1–128 UTF-8-byte item IDs within the recipient's root or component-definition scope. Sequential backward creation aliases resolve in root timeline batches; unresolved/forward creation aliases preserve the existing nonretryable VALIDATION_FAILED error. Component references use stable local IDs. Reordering preserves dependencies. Provider deletion succeeds only when all affected references are cleared or replaced in the final atomic batch, including delete-before-clear ordering. Missing scoped references return nonretryable ITEM_NOT_FOUND; malformed/ineligible/self/cyclic/excessive graphs return nonretryable INVALID_ARGUMENT. Stale revisions remain retryable REVISION_CONFLICT. Unknown fields, unsupported channels and stored null references reject. Observable raw wire duplicate keys reject; parsed MCP objects cannot recover original duplicate keys.

A provider uses an isolated transparent premultiplied linear RGBA plane: source, crop/clip, active painted masks, ordered effects, local and nearest-to-outer ancestor transforms, its own matte, then inherited opacity and transition gain. Alpha coverage is A; luma coverage is `.2126R+.7152G+.0722B` of premultiplied linear components. Red with alpha.5 yields alpha.5 and luma.1063; transparent colored paint contributes zero. Destination background and destination blend do not enter coverage. Recipient RGBA multiplies that coverage once at matching output pixel centers after transforms and before recipient opacity/transition. Hidden or inactive providers yield zero. `matteOnly:true` suppresses direct drawing alone, preserving provider coverage, audio and timing, including an unreferenced matte-only leaf.

Each component occurrence retains independent provider membership and exact clocks. A provider ID names the transparent source-over aggregate of its completed base/repeater copy planes in canonical paint order. Each copy completes its own matte and shutter average before aggregation; averaging two alternating half-alpha copies produces .25 each and aggregate.4375, rather than the forbidden aggregate-before-average.5. Ordinary direct drawing draws each completed copy once. Every recipient shutter sample queries the provider at its actual root sample time; providers honor their own shutters once and nested chains retain exact inherited clocks. No new matte animation properties or targets are added; existing provider, recipient and mask animation remains active.
