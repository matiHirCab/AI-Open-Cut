# Advanced text layout

Capability `advanced_text_layout_v1` adds optional `style.layout` to existing text creation/update inputs, including batch aliases and drafts. Schema 21 preserves layout through history, copies and reopen. Old projects migrate atomically without enabling it; absent layout retains legacy pixels and pinned fonts. Unsupported future schemas fail closed.

Example: `{"layout":{"trackingPx":0.5,"lineHeightPx":36,"bounds":{"widthPx":320,"heightPx":120},"wrap":"word","verticalAlignment":"center","fit":"shrink","backgroundCornerRadiusPx":8}}`.

All dimensions are finite text-local project pixels before transforms. Bounds include existing padding; the remaining content dimensions must be positive. Width is 1–7680, height 1–4320. At least one bound is required when bounds is supplied. Legacy wrapWidthPx supplies width if layout bounds omit it. Tracking is 0–1000 between complete visual shaping clusters, with no trailing tracking. Line height is 1–4320 per line box and fixes the baseline step across font changes; omission retains font metrics plus legacy lineSpacingPx. Fractional values are supported.

Wrap defaults to `word` (Unicode opportunities, cluster fallback), `cluster` breaks at complete shaped clusters, and `none` keeps only mandatory separators. An oversized cluster remains intact. Omitted width disables soft wrapping. Existing horizontal alignment and `top|center|bottom` vertical alignment position the line-box block; non-top requires height. Overflowing axes use zero alignment offset.

Fit defaults to `none`, retaining authored fontSize. `shrink` requires a bound and selects the largest fitting integer from 1 through authored size. `fit_width` requires width; `fit_box` requires both dimensions; both search sizes 1–1000 and can enlarge. Each candidate is shaped and wrapped using pinned faces. Padding, tracking, explicit line height and effects stay fixed. Width measures advances and height measures line boxes, excluding ink overhang and effects. If no size fits, size 1 is used with visible overflow. Text is never clipped or truncated and fitting never mutates authored state.

Background uses existing backgroundColor/backgroundOpacity and padding. Radius is 0–2160 and clamps to half the smaller padding-box dimension. It rounds the background without clipping glyphs or shadows. Ordered paint stacks remain effective.

Layout-enabled render artifacts add `textLayouts` diagnostics in evaluated paint order: `itemId` (effective instance identity), `resolvedFontSize`, `lineCount`, `contentWidthPx`, `contentHeightPx`, `overflowX`, `overflowY`. Content dimensions exclude padding/effects. Legacy-only artifacts omit the field. Frame, range, draft and export consume the same evaluated geometry. Advanced-layout range and export use H.264 medium-preset CRF 18 to preserve fitted glyph detail within the visual tolerance. Legacy encoding choices remain unchanged when layout is absent.

There are at most 1000 candidates per text, 16384 glyphs and 4096 lines per candidate, and 16777216 cumulative candidate glyphs per scene. Existing expanded-scene, raster and paint-work bounds still apply before output work. Null, unknown fields, invalid combinations, non-finite values and excessive work produce INVALID_ARGUMENT. Revision conflicts, missing items, locks, integrity and path failures retain existing errors and atomic rollback. Layout accepts no paths, expressions or network resources. Replacing style without layout restores legacy layout; omitting style preserves it.

Logical box anchors use fractional padding-box dimensions, independently of raster rounding, glyph overhang and paint margins. Effects expand the rendered ink without moving the authored box, including under animation and parent transforms. Reported widths use canonical logical-order cluster accumulation; reusing an exact reported width as a bound does not introduce an extra wrap through floating-point reassociation. Retained draft text styles, including component payloads, are validated before migration or font publication without replaying stale drafts. The cumulative candidate-glyph ceiling remains 16,777,216, inclusive, across expanded occurrences.

Persisted layout-enabled root text, including hidden items and retained undo/redo snapshots, receives canonical style validation before publication or rendering work. Structurally malformed layouts in current state, history and drafts return non-retryable INVALID_ARGUMENT, including null, invalid nested fields, wrong types and unsupported enums. Rejection preserves authoritative project, history, draft and font files. Unrelated persisted-data errors and layout-absent legacy validation behavior retain their existing classifications and semantics.
