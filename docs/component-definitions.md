# Component definitions

Schema 11 introduced `project.components` alongside the unchanged root `tracks`. Each definition contains `id`, `name`, `width`, `height`, `durationMs` and local `tracks`. Definitions do not contribute to root duration, preview or export until instance evaluation is implemented in issue #24. Status advertises `component_definitions`, not component rendering. Schema 12 adds [typed slots and instance values](template-slots.md) and advertises `typed_template_slots`.

Use `component_create`, `component_update`, or `component_delete` through headless edits or matching MCP tools. Create and update require all definition fields except `id`; update additionally requires `componentId` and replaces the entire definition. Create generates an ID. Delete accepts only `componentId`. All tools use `projectId` and `expectedRevision`; existing batch editing is supported. Only create accepts `resultAlias`, and subsequent component targets or nested component references can use `@alias`. Local item/track identifiers are explicitly supplied, not alias declarations. Responses identify changed definitions, not ambiguous local child IDs.

Component IDs are project-unique. Track and item IDs are unique inside their owning composition; matching IDs in another composition are independent. Parent references use `{scope:"component:<definitionId>",id:"local-group"}`. Root references retain `scope:"root"`. Transitions also reference local endpoints. Existing root editing operations retain root-only lookup. Use full definition replacement to edit local content. An update cannot modify or remove a locked local track or change the relative order of locked tracks; deletion requires every local track unlocked. Root track locks do not independently block definition management.

Coordinates use a top-left origin, positive X right and Y down. Normalized transforms refer to the definition dimensions. Local time uses integer milliseconds and half-open intervals. Explicit positive duration bounds every local item; there is no automatic duration inference. Flat track/z-index/stack-order conventions remain unchanged.

A nested `component_instance` is stored only on a definition's overlay track. It has `id`, `componentId`, `startMs`, `trimStartMs`, `durationMs`, finite positive `timeScale`, and common static visual/order/parent fields. Its parent interval must fit the containing definition; `trimStartMs + durationMs * timeScale` must fit the referenced definition. No clamp, loop or implicit fallback occurs. Root placement, instance transition endpoints and legacy instance animation are rejected pending evaluation support.

Limits are 512 definitions, a longest dependency path of 16 edges (leaf depth zero), 4096 aggregate component tracks and 4096 aggregate stored component items. Existing per-composition graph and keyframe bounds still apply. New time values cannot exceed JavaScript's maximum safe integer; dimensions follow project bounds (7680×4320). All definitions are validated, including hidden or unused content. Repeated references and acyclic sharing are valid; duplicate IDs, cycles and cross-scope references are not.

Missing definitions return `ITEM_NOT_FOUND`; malformed definitions, duration/graph bounds and deletion of a referenced definition return `INVALID_ARGUMENT`. Locks use `TRACK_LOCKED`; stale revisions use retryable `REVISION_CONFLICT`. Existing batch-envelope and alias-format failures retain their existing codes. All mutations commit as one revision/undo step or preserve the complete prior project and history. Undo, redo, reopen and durable drafts retain exact component state and media ownership.

Opening supported schemas 1–10 migrates current state and all retained undo/redo snapshots atomically to schema 11 with an empty component collection. Root content, revisions, media and rendered output remain unchanged. Schema 11 requires `components`; older binaries cannot read it, and no downgrade is provided. Unknown future versions fail closed. Assets referenced only in definitions, drafts or retained history remain protected by existing integrity and garbage-collection rules.

Component-local keyframe timestamps, media fade durations, caption generation timestamps and source word times must also fit JavaScript-safe integers. Volume keyframes require media items. This does not impose new keyframe-within-item or fade-within-duration restrictions.

Component caption provenance requires nonblank provider/model IDs (at most 128 UTF-8 bytes), nonblank language, optional nonempty model version, nonblank original text (at most 4096 UTF-8 bytes), nonblank words, and optional finite confidence in [0,1]. Generation time is positive; each word has start < end. Bottom margin is at most 4320. Words describe original source provenance and may lie outside a moved or trimmed caption's current interval; updates retain them unchanged. Empty words and omitted optional confidence remain supported. Invalid nested content fails with INVALID_ARGUMENT, including on current/history reads, without automatic repair.

Schema 12 preserves the definition behavior above while adding required slots and nested slotValues fields. Requests remain compatible: create defaults slots to empty, update omission preserves slots, and nested request omission defaults slotValues to empty. See [typed template slots](template-slots.md) for bindings, limits, atomic replacement and migration.
