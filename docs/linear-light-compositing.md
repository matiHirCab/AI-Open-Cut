# Linear-light scene composition

Query headless `status` with `protocolVersion: 1`, or MCP `editor_get_status`, and check `subsystems.rendering.ready` plus `linear_light_compositing_v1` in its `capabilities`. The same capability appears in the top-level capability list when rendering is ready. `evaluated_scene_rendering` alone does not identify the corrected linear-light pipeline. When required local rendering dependencies are unavailable, the rendering capability list is empty, its readiness error remains `DEPENDENCY_UNAVAILABLE`, and overall editor readiness can still be true. The bridge preserves the headless rendering capabilities without advertising unavailable support.

The capability identifies the shared frame, range, draft and export scene compositor for every currently supported visual source. Decoded local SDR RGBA enters a floating-point, premultiplied linear sRGB representation. Crop, ordered local effects, affine sampling, matte coverage, temporal averaging, opacity and the supported linear blend modes preserve that representation; the completed scene converts to the existing 8-bit SDR output boundary over opaque black. Exact half-alpha white over black produces approximately 188 per output channel. Existing translucent overlaps and resampled edges intentionally change from encoded-space blending. Geometry, clocks, audio and opaque identity content retain their existing semantics.

Existing source rasterizers own local text/vector paint and clipping; the compositor does not recover precision already quantized by those rasterizers. Schema-33 masks multiply premultiplied source pixels after source crop and clipping, before effects and affine mapping; Schema34 introduced [scoped track mattes](track-mattes.md), which apply private provider coverage after recipient affine mapping and before inherited opacity. Schema35 introduced the seven [destination blend modes](blend-modes.md). Schema37 adds explicit [controlled group composition](group-compositing.md): transparent local children, composition-bounds clipping before ordered owner effects, and outward transform/opacity once. Uncontrolled groups retain legacy flattening. See [mask rendering](mask-rendering.md) for mask support, animation and resource certification. Render preflight bounds composition memory/work and certifies fractional native video source timestamps to a conservative 1ns arithmetic error; unsafe combinations return `INVALID_ARGUMENT` before resource creation. Exact whole-millisecond samples retain the existing backend compatibility, and image sources decode at zero. These render limits do not change authored time validity or project history. The original linear-light capability added no authored fields, operations, migration or schema version. Later mask, matte, blend and group-compositing features have their own versioned model contracts; HDR, arbitrary color profiles and output-color controls remain unsupported. Existing protocol-v1 clients remain valid and may ignore the unique additive capability.

Canonical catalogs are `contracts/headless-protocol-v1.json` and `contracts/mcp-surface-v1.json`; governed consumers and review ownership are listed in `contracts/contract-ownership-v1.json` and ADR 0002. The approved issue #49 MCP change adds only the capability identifier. The expanded catalog digest is deliberately pinned to `2a3fdf15aec5472e1cc2001f47659d4591de02e0f02bdeece3384584ea174503`; removing that sole identifier reproduces the prior digest `181c60179f3d9f329417093315b0b6058a9093fd8e1c23e06cee83c4c19b2620`. Contract tests verify both digests and retain all reference-expansion, live tool schema and annotation checks.

Contract changes require designated CODEOWNER review and `bun run contracts:check` alongside the repository's complete implementation and conformance checks.
