# Motion graphics release guide

This is the current MG-M6 entry point for the native editor and local MCP bridge. Check `editor_get_status` and MCP tool discovery against the running binary before authoring. Current headless JSON-lines **protocolVersion is 1** and persisted **projectSchemaVersion is 44**. Headless protocol version is independent of MCP wire negotiation, SDK package versions and feature catalog versions. The private example below has `exampleVersion: 1`; it is teaching data, not a public contract. Artifact delivery uses content policy `artifact_resources_v2`, independently of protocol and project schema versions.

## Canonical semantics and compatibility

[Contract ownership](../contracts/contract-ownership-v1.json), [ADR 0002](adr/0002-cross-language-contract-ownership.md), [headless protocol](../contracts/headless-protocol-v1.json), [MCP surface](../contracts/mcp-surface-v1.json) and [error codes](../contracts/error-codes-v1.json) govern public compatibility. Catalog version 1 does not imply persisted schema 1. The preparatory [motion vocabulary](motion-graphics-contract-fixtures.md) remains distinct from each activated feature's runtime catalog. Its historical schema numbers describe activation milestones; use status for the current persisted version.

[Definitions](component-definitions.md), [evaluation](component-evaluation.md), [typed slots](template-slots.md) and [lifecycle](component-lifecycle.md) own component rules. Coordinates have a top-left origin, X right and Y down; normalized transforms refer to the owning composition. Local intervals use integer milliseconds and half-open bounds. Instance timing must fit the referenced definition; no implicit clamp or loop repairs invalid timing. Local IDs and scope remain composition-specific. Existing track, z-index and stack order conventions apply. [Transform2D](transform2d.md), [animation channels](animation-channels.md), [inherited clocks](inherited-animation-timing.md), [marker timing](marker-relative-timing.md) and [motion blur](motion-blur-sampling.md) define their respective transforms, clocks and sampling.

Use [shapes](shape-items.md), [SVG](svg-ingestion.md), [grids](procedural-grids.md), [repeaters](repeaters.md), [text layout](text-layout.md) and [advanced text layout](advanced-text-layout.md) for their actual constraints and fallbacks. [Linear light](linear-light-compositing.md), [masks](mask-rendering.md), [blend modes](blend-modes.md), [effects](parameterized-effects.md) and [groups](group-compositing.md) own compositing order. Font resolution and feature-specific fallback do not authorize guessed substitutions or unsupported effects.

Standalone writes use `projectId` and `expectedRevision`. Creation aliases inside `timeline_batch_edit` resolve only to earlier creations and return real IDs. Local names and slot strings stay literal. `component_instance_update` supplies the complete component/timing tuple; omitted `slotValues` preserves stored overrides, while an explicit map replaces them. Successful batches produce one revision and one undo step. Invalid mutations leave authoritative project and history bytes unchanged. `REVISION_CONFLICT` is retryable: read current state and reconstruct the intended edit. Missing definitions use `ITEM_NOT_FOUND`; invalid cycles use `INVALID_ARGUMENT`, both nonretryable. Consult the error catalog for other operations rather than treating every failure as transient.

## Executable teaching example

The [private JSON corpus](examples/motion-graphics-release-v1.json) creates a fresh 64×64, 10 fps project, then a standalone rectangle definition at revision 0. At revision 1 its four-operation batch creates `@definition`, defines a numeric opacity slot, inserts `@instance` and moves it to 250 ms while preserving its 0.6 override. The batch returns revision 2 and real definition/instance IDs. Substitute `$runtime:projectId`, `$runtime:overlayTrackId` and `$runtime:standaloneComponentId` with IDs returned by that run; keep `@definition` and `@instance` literal for core alias resolution. These fixture revisions assume a fresh project and are not general concurrency defaults.

The same file contains four genuine domain refusals: a schema-valid self-cycle, missing definition, stale revision against an existing definition and a late batch failure after four valid operations. [Private metadata controls](../apps/agent-bridge/tests/release-documentation.test.ts) reject version, case, retryability, binding and link drift. [Actual MCP workflow](../apps/agent-bridge/tests/release-documentation-workflow.ts) checks discovery/status, returned IDs, single revision/undo count, preserved bytes for every refusal, undo, redo and disk reopen. Both [source integration](../apps/agent-bridge/tests/smoke.test.ts) and [compiled smoke](../apps/agent-bridge/tests/packaged-smoke.test.ts) execute it through actual clients. Run `bun run test:unit`, `bun run test:integration` and `bun run test:smoke` in `apps/agent-bridge` with the pinned repository toolchain. This teaching sample does not exercise rendering, speech inference, bridge restart or desktop interaction.

## Opening existing projects

[Persistence and recovery](project-persistence.md) owns durable transactions and recovery. The core migrates supported current state and all retained undo/redo snapshots together under the project lock, preserving provenance and media integrity. It refuses unknown future current or retained schema versions without rewriting documents. Canonical [migration tests](../crates/editor-core/src/migrations.rs) include `migrates_current_and_retained_history_together`, `rejects_unknown_future_schema_without_rewrite` and `rejects_future_retained_schema_without_mutating_any_document`. Back up the whole managed project before changing runtime versions; do not manually rewrite `project.json`, history or schema numbers to downgrade. Schema 13 in early component documents is an activation milestone; the current runtime persists schema 44. This documentation change introduces no migration or public request change.

## Operational readiness

[Bridge setup](agent-bridge.md) and [renderer packaging](platform-renderer-packaging.md) describe configuration and backend selection. Editor readiness does not imply rendering, every optional FFmpeg filter, speech or transcription readiness. Read each `editor_get_status.subsystems` ready flag and capability list. Resolved path diagnostics are operational information; existing structured error/log redaction protects paths, tokens and private provider details. Provider readiness may require separately installed models and workers. Missing required dependencies use existing nonretryable `DEPENDENCY_UNAVAILABLE`; correct configuration or install the supported dependency before resubmitting rather than relying on silent degradation.

`preview_render_frame`, `preview_render_range`, `preview_review_range`, `project_export_video` and `audio_analyze_mix` expose their existing workflows. [Preview review](preview-review.md) owns review resolution/audio defaults; legacy range defaults remain unchanged. [Audio DSP](audio-bus-dsp.md), [ducking](audio-bus-ducking.md), [analysis](audio-analysis.md) and [master normalization](master-normalization.md) require the corresponding runtime capabilities and native filters. Do not infer them from editor readiness. `speech_generate_and_insert` is provider-neutral; `tts_generate_and_insert`, `tts_get_status` and retained-artifact commit remain compatible published tools. Consult discovered schemas and [speech alignment](speech-alignment.md) before invoking them.

[Artifact delivery](artifact-delivery.md) defaults job polling to metadata and resource links. Explicit `resources/read` uses an opaque URI scoped to the owning bridge process. `includeBinary: true` permits PNG/WAV inline delivery; MP4 remains a resource link. Jobs, resource ownership and retained tokens are process-local and subject to expiry/eviction; reopening a project does not restore them. Selecting an active project is not an authorization boundary. Preserve the documented trusted-LAN authentication and redaction behavior.

## Independent release evidence

[Complete reference scene](complete-reference-scene.md) preserves all ten capability groups and its 67-operation recipe: six seconds at 192×108 and 10 fps, fixed fonts, synthetic audio and marker cues, actual PNG/range/H.264/AAC checks, history and reopen. Its generated audio and estimated alignment are not speech inference or listening-quality evidence. [Desktop review](desktop-review.md) documents the separate actual GUI inspection. The small teaching corpus cannot replace #70's marker fixture or #77's complete scene.

[Release gates](motion-release-gates.md) retain source and packaged MCP, public contracts, providers, native media, deadlines, pixel/audio goldens and all three platform CI matrices. Eligible direct Linux/Windows native backend identity supports verified warm reuse; the existing unsupported Mach-O identity path remains a deterministic uncached fallback. The #15 performance report is report-only, not a universal budget. Require terminal success at the published exact head, including the aggregate required check, before calling a release verified. Draft PRs target `main` and retain prior verified issue changes; publication does not merge or deploy.

The proposed editable 15–20 second rescue-video benchmark is a separate visual-quality target. Creative additions, renderer redesign and broad fixture deduplication require their own approved scope; none replaces existing acceptance here.
