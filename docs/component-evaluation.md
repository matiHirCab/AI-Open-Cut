# Component instance evaluation

Schema 13 activates root overlay instances. Protocol 1 advertises `component_instance_evaluation`. Definitions remain shared and immutable during evaluation; placing an instance adds its active interval to the root timeline. Frame preview, range preview, draft preview and export use the same core scene and rendering path.

Use `add_component_instance` with `trackId`, `componentId`, `startMs`, `trimStartMs`, `durationMs`, `timeScale`, and optional `slotValues`, `transform` or `transform2d`, `hidden`, `zIndex` and root `parent`. Identity, transform, visibility and order defaults match ordinary root items. `component_instance_update` accepts `itemId` and the complete component/timing tuple; omitted `slotValues` preserves overrides and an explicit map replaces them. Both are headless edits and standalone MCP tools with `projectId` and `expectedRevision`. Aliased batches can refer to earlier definition/instance creations; only creation produces `resultAlias`.

For parent time `t`, local time is `trimStartMs + (t - startMs) * timeScale`. The instance is active on `[startMs, startMs + durationMs)`. Nested clocks compose without intermediate millisecond rounding and intersect all enclosing active intervals. Persisted times remain nonnegative safe integers; duration and rate must be positive, and the mapped source endpoint must fit the referenced duration. Media source trims, local animation, captions, fades and internal transitions retain their local clocks.

Instance position uses parent composition coordinates and anchors use referenced component dimensions. Static instance/group/local matrices and opacity compose in hierarchy order. Dimensions do not imply scaling to fit or clipping at component edges: only the existing root canvas bounds clip output. Each occurrence forms a contiguous stacking block in its parent's track/zIndex/stackOrder/stable-ID order; descendants retain their local order. Local identifiers cannot collide across occurrences.

Overrides precede defaults and an absent optional value keeps the base property. Text, styled rich text, color, opacity, visibility, alignment, duration and managed-asset bindings are resolved independently. Rich text preserves run colors, bold/italic and line breaks. Styled fonts resolve matching faces beside the configured font (common Bold/Italic/Oblique family suffixes); an unavailable style returns `DEPENDENCY_UNAVAILABLE` during preparation instead of silently discarding style. Existing font/path checks and renderer failure codes remain in effect.

Hiding an instance or its containing track suppresses all content, including audio. Ordinary group visibility and visual clipping affect pixels; they do not mute audio. Audio retains track roles, mute, gain, fades, automation and mapped voiceover ducking. Cumulative media rates are bounded inclusively to `[2^-32, 2^32]`; audio uses at most 32 pitch-preserving tempo stages with factors in `[0.5, 2]`.

The evaluator validates hidden and unused definitions before rendering. Existing graph depth (16), storage, slot and geometry bounds remain. Expansion visits at most 65536 item occurrences including hidden items, groups and instances, and enforces 4096 visual layers, audio layers, media resources and transition facts, plus 10000 keyframes per channel and voiceover activity ranges. Non-finite derived clocks or transforms and limit violations return `INVALID_ARGUMENT` before backend execution.

Generic root movement, duplication, deletion, static transforms, visibility, ordering and parenting apply. Instance keyframes, splitting and instance transition endpoints remain unsupported (`INVALID_ARGUMENT`). Track locks, atomic batches, revisions, drafts, undo/redo, reopen and asset retention use existing core rules. Missing definitions return `ITEM_NOT_FOUND`, invalid slots/timing return `INVALID_ARGUMENT`, and stale revisions return retryable `REVISION_CONFLICT` without partially changing project/history.

Opening schema 12 upgrades only the version to 13 while preserving components, slot values, root content and retained history under the project lock. Older schemas follow their existing migrations first. Root instances in pre-13 persisted documents are rejected, and unknown future schemas fail closed. Older binaries cannot read schema 13; no downgrade is provided.
