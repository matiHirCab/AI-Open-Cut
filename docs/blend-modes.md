# Blend modes

Project schema 35 adds the optional, non-null `blendMode` field to image/video, Text, solid color, rectangle, Shape, SVG, Grid and Caption leaves. Choices are `normal`, `multiply`, `screen`, `overlay`, `add`, `darken`, and `lighten`. Omission defaults to Normal in stored items, preserves the existing mode in `update_item`, and explicit Normal resets the selection and is omitted on serialization. Null, other spellings, unknown values and observable raw duplicate fields reject. Non-visual containers, audio and transitions permit only absent/Normal; containers do not create isolation groups.

Use `timeline_update_item` or the existing batch/draft operations. Creation aliases can select the newly created leaf in the same atomic batch. Core/headless malformed decoding returns `INVALID_ARGUMENT`. MCP structural schema failures retain the existing SDK `isError`/text envelope and reject before the handler; handler-level domain failures retain structured core errors. A parsed MCP object cannot reveal raw duplicate JSON keys.

Compositing uses premultiplied linear RGBA over the existing opaque black scene. Normal keeps the original f32 source-over arithmetic. Other modes first validate and clamp in the same canonical f32 domain, then evaluate finite f64 equations. Overlay branches on the backdrop component; Add saturates the unassociated color sum. Zero alpha is handled without an epsilon cutoff. Color fragments, including multiline Caption glyphs and its background box, assemble into one source-local plane. Crop, masks, effects, affine placement, matte coverage, opacity and transitions precede the owning shutter average; one direct blend follows that average in paint order. Provider planes always use Normal source-over, independently of their own selected direct mode and the destination.
