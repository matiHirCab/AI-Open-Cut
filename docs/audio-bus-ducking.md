# Narration bus ducking

Schema43 adds optional `ducking` to the four built-in audio buses. `audio_bus_set_ducking` accepts `busId` and a closed block with required `enabled`, `sourceBusId`, `gain` (finite0..1), `attackMs` (integer0..2000) and `releaseMs` (integer0..9000). Source must be an existing different bus. Omission retains the old shape; disabled or gain1 controls remain inspectable identity. No raw filter, expression, path or external resource is accepted.

This is conservative narration **clip activity**, continuing the existing narration-envelope approach. Every selected positive-base-gain audio clip reaching the source bus contributes its full selected span, including upstream routed buses. Hidden/muted/excluded clips and zero base item gain contribute no activity. Fades, automation and silence inside a decoded file do not turn this into amplitude detection: automated-away material can still contribute clip activity. Captured event routing takes precedence over track routing, then role fallback. Component activity uses precise clipped root clocks.

Adjacent or overlapping source intervals merge. Attack ramps from1 at `start-attackMs` to the configured gain at start; clipping before0 retains the full denominator. Gain holds through source activity and releases linearly to1 at `end+releaseMs`. Overlapping envelopes take their minimum. Zero attack/release changes instantaneously at the half-open boundary. No tail, timeline duration, source offset or playback rate is added. Source activity is evaluated before bus processors, so source references do not create detector feedback or signal graph edges; master/shared downstream choices are explicit inspectable intent.

Saved per-track role ducking stays unchanged before item summation. Explicit opt-in bus ducking composes after summed gain→ordered EQ→linked compression and before stereo balance→output bus; every bus/master runs once. Applying both a saved role setting and an explicit bus setting intentionally composes them. Omitted/disabled/gain1/no-source/no-positive-target controls retain the exact previous scene, Debug, plan/filter and native output behavior, including existing DSP.

Complexity remains canonical: four fixed route nodes,4096 selected audio layers,64 merged intervals per configured source and512 bounded piecewise envelope segments per bus, with resource/work admission before I/O. Excessive work and malformed settings/references fail nonretryable `INVALID_ARGUMENT`; stale requests retain retryable `REVISION_CONFLICT` precedence. Fixed bus setters cannot create aliases. Standalone, ordered batch and materialized-draft transactions retain one revision/history entry, atomic rollback, undo/redo and deterministic reopen. Every supported1..42 current/undo/redo generation adopts43 atomically without invented controls; premature/null/mixed invalid/future generations fail before publication, with unchanged complete-generation journal recovery.

`audio_bus_ducking_v1` rendering support is conditional on existing base readiness plus `volume`, `aformat` and `pan`. Actual active DSP still requires its five existing filters. Missing support fails `DEPENDENCY_UNAVAILABLE` after model/resource validation and before workspace/collision/raster/process/artifact effects. Storing/editing settings is independent of render availability. The protocol remains1, with one additive tool/operation/capability; every frozen predecessor catalog and native tolerance is retained.

Frame/range/draft/export consume the same evaluated semantics. Required CI runs independently authored numerical and real FFmpeg references for attack/release/minimum/zero-time/clipping/routing/event/component/DSP/legacy/silence cases, with unchanged stereo/mono RMS, RGB and timing tolerances, alongside every original native/raster/lifecycle/contract/source/package gate.
