The font directory must contain the unchanged regular, bold, oblique and bold-oblique files. `scripts/setup-platform-renderer.py` prepares them in CI and fails on missing dependencies or changed hashes. No model download, inference service, external media or network SVG is needed for the synthetic fixture.

## Measurement scope and cleanup

Only this Linux x86_64 default release workload has the private inclusive envelope: each capture elapsed<=600000ms and sampled process-tree resident bytes<=2147483648. Windows/macOS report observations without those numerical promises. These are verification bounds, not public admission limits or fine regression percentages.

Timing is direct monotonic whole-capture elapsed, including preparation, output comparisons, oracles and sampler synchronization. Memory is the maximum observed sum of the isolated test process and recursively discovered native descendants. Sampling uses a5ms sleep plus process-refresh cost; it is not a guaranteed5ms wall-clock period or an unsampled true-peak claim. Compilation, Cargo and unrelated sibling tests are excluded from the measured root. Each capture requires positive safe counts, resident observations and an actual native descendant. Reports reject unknown/missing fields, wrong version/scope/nonce/build/platform/fixture/font identity, invalid numbers, wrong capture counts, false witnesses and exceeded applicable bounds.

The #15 schema3/stage-definition2 baseline remains unchanged and report-only. Its non-additive observations are neither subtracted nor compared against this different workload, architecture, toolchain or environment. CURRENT is not rebaselined.

The private ownership runner preserves diagnostics and returns failures. Unix uses an owned session/group, identity-checked descendant discovery and Linux subreaper cleanup for detached/orphan descendants. Windows assigns the suspended root to a kill-on-close job before resuming its primary thread, so children inherit ownership. The Windows APIs follow [job assignment](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-assignprocesstojobobject), [thread enumeration](https://learn.microsoft.com/en-us/windows/win32/api/tlhelp32/ns-tlhelp32-threadentry32) and [ResumeThread](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-resumethread). Actual native descendant controls test timeout, nonzero exit and successful parent exit; Unix controls deliberately detach the child. Previous production cancellation code and1500ms/5000ms assertions remain unchanged.

Each run owns a fresh nonce directory, full command logs, closed inventory, requested/checked-out source identity and an explicit dirty-source flag, default report/frame/video, source/compiled MCP evidence/video and a final acceptance marker. Missing/empty required artifacts are failures. CI uploads real evidence and partial failure diagnostics; an upload does not imply successful acceptance. Final acceptance requires the published head's terminal three-platform release jobs and all predecessor required/focused jobs. Local Linux results do not establish another platform's native behavior.

Windows release CI resolves the unique direct FFmpeg/FFprobe sibling pair in the installed Chocolatey7.1.1 package tools tree before dependency setup. Chocolatey's bin executables are [forwarding shims](https://docs.chocolatey.org/en-us/features/shim/); the existing core intentionally bypasses optional cache identity for forwarding executables. `scripts/setup-motion-release-backends.py` refuses absent, ambiguous, escaped, unsafe or non-native/direct candidates before publishing PATH. Hermetic setup controls are synthetic file-selection tests, never native media evidence. The complete actual Windows workload still requires warm final-encoder reuse and the original MCP cache trace; no Windows cache fallback or renderer change is introduced. The earlier d568f3d7 failure and its uploaded diagnostics remain retained.
