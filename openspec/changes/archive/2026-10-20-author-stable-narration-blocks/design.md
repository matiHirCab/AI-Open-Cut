## Decisions

### Planning and Unicode

Use the already pinned unicode-segmentation1.12.0 UAX29 sentence iterator in core. Automatic boundaries are deterministic suggestions, not linguistic correctness claims; abbreviations such as Dr./e.g. are frozen in fixtures and callers can override suggestions. Source text is exact (no normalization before offsets). Manual boundaries are strictly increasing end offsets in Unicode scalar values, with final end equal to source scalar count; reject empty/blank spans, surrogate-like invalid UTF8, out-of-range/duplicate/reversed ends. Paragraph ordinal derives from preceding LF blank-line paragraph separators; paragraph/source order is never sorted by ID. Do not use JS UTF16 indices or split graphemes through an automatic fallback. At most32 blocks, source<=32768 UTF8 bytes; every original/display block and resolved spoken block<=4096 UTF8 bytes and<=min(4096, provider maxTextCharacters) Unicode scalars. Overlong automatic sentences require explicit manual boundaries, never silent truncation or timestamp interpolation. Limits are validated before any synthesis.

Core plan pins an explicit profile UUID/expectedVersion once and snapshots its effective settings into every block. It returns a fresh manifest UUID, fresh block UUIDs and exact source spans/display text/effective requests. Planning is read-only: no project edit or migration is necessary. A caller's JSON plan is untrusted at commit; core revalidates structure, IDs, bounds, source spans, profile attribution/settings and generated provenance, without reconsulting the current library. Changed library versions cannot change a retained plan.

### Spoken text and synthesis

The separate bridge block workflow uses existing prepareSpeechSegments on each resolved request, stores the exact ordered returned segments and joins them with LF as spokenText (a textual separator, never an audio timestamp). It estimates every block against current real provider capabilities before generating any block. Request normalization/pronunciation/chunking and sentencePauseMs retain existing behavior. Expansion is checked on resolved text as well as raw text; unsupported provider/voice/language/speed errors are unchanged. Generation uses ordinary retained previews in order; cancellation/partial failure returns the already completed preview tokens within their existing retention, with no project mutation. No source or provider field invents alignment. Optional returned alignment retains exact native/forced/estimated quality and producer identity.

CLI is source-only, persistent bounded JSON-lines session (plan/preview/commit/discard), so expiring process-local tokens are not advertised as durable across command processes. No new MCP catalog or installed UI surface. The application service and its public test seam remain provider neutral; production CLI reuses existing configuration/provider construction and headless owner. Shutdown waits active work/cancellation and owned cleanup.

### Atomic complete-preview publication

One additive service method reserves a distinct ordered set of at most32 existing tokens synchronously before awaiting core. Clear their existing expiry timers while leased; reject concurrent lease/commit/discard of the same token. Snapshot all metadata and verify the entire plan/token/request correspondence before publication. Call one core commit_narration_blocks; NEVER loop over commitPreview. Every generated descriptor includes owned path, duration, exact origin/alignment/probe and display/placement data. Core resolves paths under existing generated-media policy, locks the project, stages current/history migrations and existing draft updates, imports all generated resources through UncommittedResources, applies normal native add-audio/caption/cue edits and validates the complete final manifest/candidate before one recoverable publication. Extend the existing staged-edit private callback with the tracked resource ledger if necessary, retaining ordering and fault phases for all existing callers. No parallel transaction implementation.

Core assigns native asset/item/caption/cue UUIDs once and returns their mapping. Block IDs and source/profile snapshots come from the reviewed plan and are persisted unchanged. Sequential placement uses actual generated durations and explicit caller startMs, with checked safe-integer addition and existing track/component/timeline limits. Caption/cue creation is opt-in and consumes only actual provided alignment; missing requested granularity fails, no duration-based subdivision. Default creates no caption/cue and explicit empty owned references. Native track locks and existing aliases/errors/one revision/one undo step are retained.

Consume tokens and clean their owned temporary outputs only after authoritative core acknowledgement, including existing post-journal success-with-warning semantics. Revision conflict or validation/persistence failure before commit returns every still-valid preview to original retention without inference; expiry during a lease is handled after settlement. A transport failure with uncertain publication must report uncertainty, quarantine retained metadata and prohibit any republication of those tokens; explicit reconciliation can acknowledge only an exact published manifest, while absence/mismatch stays unknown. Never claim rollback or retry automatically. Postcommit cleanup failure is a warning, not a failed commit. Expired/discarded/duplicate/missing/mismatched previews fail before project mutation.

### Persisted identity and existing edits

Project schema47 adds narrationManifests: ordered bounded manifests (<=32/project, <=256 live blocks/project). Each stores UUID, sourceText and blocks with UUID, scalar span, paragraph ordinal, displayText, spokenText/segments, exact effective request/profile attribution, native speech itemId/assetId and explicit captionIds/cueIds. Metadata size is bounded before serialization. Native root items are the source of actual placement/duration. Manifest validation checks unique IDs globally across manifests, nonoverlapping ordered source spans, exact display slices and nonblank bounded wording; every binding names the expected existing root audio item and generated speech asset, with identical request attribution/settings. Owned caption/cue IDs exist in the correct root scope, are unique across blocks, and when created from alignment retain exact supplied text and times. Generated audio assets remain retained through existing item/current/history resource ownership; manifests introduce no external file references.

To preserve consistency, legacy edits that would delete/replace/mutate an owned item's asset binding or delete an owned caption/cue fail core validation atomically. Ordinary audio gain/visibility and caption style edits remain valid when frozen semantic bindings remain valid; move/trim requires detachment. An explicit detach_narration_block operation removes only that block's ownership metadata, leaving all native content intact; remaining blocks retain exact bytes/order/identity/provenance and a last removal removes the now-empty manifest. This is a deliberate escape hatch before legacy regeneration/deletion, not #210 repair. Undo/redo restores both ownership and native content. A later #210 will define atomic rebind/replacement and timing review. No implicit propagation, source-text resegmentation or ID regeneration on reopen.

### Compatibility, migration and ownership

Core model owns DTOs, validation owns manifest invariants, store owns transaction orchestration; no new private-owner edge. Headless serializes/dispatches, bridge owns provider preparation and preview leases, desktop remains presentation-only. Canonical narration-blocks-v1 fixture covers positive/negative wire/planning/persistence cases; ownership index and CODEOWNERS name native/TS consumers. Add only uniquely named operations; keep prior wire tags/MCP/provider shapes. Keep exact predecessor inverse assertions for schema/status/project catalog deltas; do not derive expected fixtures from implementation outputs.

All supported schema1..46 current/history generations adopt empty manifests under existing lock/transaction migration. Existing EditDraft v2 operation envelopes remain unchanged and replay on the migrated base. Metadata declared on older versions (including explicit null/empty introduced fields) is rejected before publication; current schema requires a real manifest array and future versions fail closed. Transaction recovery validates complete introduced metadata consistently. No source library/provider lookup on reopen/history/render. Upgrade is source/local development only; no deployment. Rollback requires restoring an older full project/history generation, not silently dropping schema47 metadata.

## Risks / Trade-offs

- Manual boundaries require Unicode scalar counting → explicit offset units, emoji/combining/CRLF fixtures and source CLI examples.
- Provider expansion can exceed a block budget → preflight all resolved wording before inference; no recursive silent chunking.
- Retention and concurrent commits → synchronous bounded leases, exact original expiry restoration, cancellation/fault/cleanup tests.
- Existing generic edits can invalidate ownership → one core validator and explicit detach escape hatch; test late-batch rollback and unchanged unrelated blocks.
- Resource limits on this cloud host → new /tmp checkout/target/cache; originals and backups remain untouched; report unavailable mandatory checks rather than deleting files or weakening gates.
- Shared declaration edits may later need owner reconciliation with private #208 → no access or automatic integration; no claim of cross-PR interoperability.

## Review precision 2026-10-20 (authoritative refinements)

The closed shapes, exact budgets, uncertain-state transitions and literal oracles in wire-plan.md are part of this design and override shorthand above. In particular:

- displayText is the exact source slice including whitespace; request.text is displayText.trim(), matching the existing resolver. No existing speech resolver is changed. spokenSegments/spokenText are bridge-declared preparation intent, not core-certified transcription or alignment. Core validates their bounded structure and LF-join consistency; bridge verifies them against prepareSpeechSegments of the exact leased generated request immediately before commit. Core checks request equality against actual supplied generation provenance but does not duplicate pronunciation or NFC resolution.
- Audio placement/source interval and owned caption text/timing/cue name/time are frozen binding snapshots; existing edits may change nonsemantic presentation/audio controls, but timing/reference/text changes require explicit detach first. Duplicating native content creates an unowned copy, never copied ownership; splitting an owned interval invalidates the original and fails atomically. Removing one ownership record allows gaps in the remaining ordered nonoverlapping source spans without changing them.
- Drafts retain EditDraft v2 and operations; they DO NOT acquire project schemaVersion or narrationManifests. Existing drafts replay on a migrated base, then the same final candidate validator rejects invalidating edits atomically. New dedicated planning/commit/detach headless operations are not EditOperation variants and cannot be smuggled into drafts/batches. Journal-linked existing draft updates retain their established transaction semantics.
- A group with an uncertain acknowledgement is quarantined against all consumption/discard/expiry paths. Explicit read-only reconciliation under the project lock can acknowledge an exact current manifest and consume tokens; absence or mismatch cannot prove rollback and cannot authorize replay. A terminal abandon operation/close waits all involved core calls to settle, disposes only process-owned temporary files, returns publicationUnknown without claiming rollback and permanently retires the tokens. No uncertain token can ever be republished.


Effective request trimming for new narration blocks uses the ECMAScript String.trim whitespace/line-terminator set, matching the existing bridge resolver: U+FEFF is trimmed and U+0085 is retained beside meaningful text. Core planning and immutable span validation use that same explicitly pinned set; original display slices remain exact. Existing legacy speech preparation/blank validation, profile resolution and #208 remain unchanged. Literal manual-boundary FEFF/NEL cases are shared by native planning and bridge preparation tests.
