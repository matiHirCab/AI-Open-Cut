## Context

Issue #38 is MG-M3-01 in the motion-graphics plan. The current editor-core `Keyframe` union supports position, uniform scale, opacity, and volume with five legacy easings. The project schema is 21. A canonical motion-graphics fixture already sketches channel names, but those fixture-only concepts are not active runtime contracts. Prerequisites #11 and #17 are closed. This design follows the delta specs in this change and ADR 0002/0003.

## Goals / Non-Goals

**Goals:** Establish a closed typed channel model, first supported channel edits and sampling, additive agent transport, schema-22 migration, and exact cross-language fixtures. Preserve legacy output and transaction behavior.

**Non-Goals:** Activate unsupported crop, source, path, gradient, effect, rotation, skew, anchor, playback-rate, or pan rendering. Later issues #39–47 own curves, markers, loops, inheritance, full property rendering, blur, presets, and comprehensive lifecycle transformations. The channel catalog lists these names and value shapes for discovery, but write validation rejects them until their evaluators exist.

## Decisions

1. **Store channels beside existing keyframes.** Add an optional `animationChannels` collection to applicable timeline items and component-local items, with an empty default. Keep the existing `keyframes` array and `set_keyframes` request byte-compatible. Reject effective-property collisions between old and new representations. Alternative: replace `Keyframe` in place; rejected because persisted projects and older clients would change meaning.
2. **Use typed channel identity and value variants.** A closed channel discriminator identifies property and optional scoped target; the value variant is checked by editor-core. Versioned canonical fixtures declare each channel's value tag, prospective target kind, activation state, and named limits. Active entries declare finite numeric bounds; inactive entries carry an explicit deferred-bounds marker and gain bounds only when their renderer milestone activates them. Rust and TypeScript parity tests compare every catalog entry and exercise valid, invalid, and inactive envelopes. Transport Zod schemas guard wire shape and size; semantic validation remains solely in core. The bridge HeadlessEdit union uses the schema-derived channel input type. Alternative: property strings plus arbitrary JSON values; rejected because mismatches and unsafe renderer payloads would become possible.
3. **Activate only properties the shared renderer can honor in this milestone.** Position X/Y, independent scale X/Y, opacity, and audio gain are sampled by `EvaluatedScene`. Visual channels target legacy-transform visual items and use absolute pixel position and absolute independent scale factors; `transform2d` conflicts in either edit order until dynamic affine semantics are implemented. Audio gain is decibels [-96, 12], converted to a linear multiplier on the existing media audio volume. Other catalog names are discoverable as inactive and fail edit validation. Existing projects with no new channels follow the preexisting path. Alternative: persist inactive channels now and ignore them in render; rejected because saved edits would falsely appear to work. Alternative: implement every property in #38; rejected because #43 and the effect milestone own those renderer semantics.
4. **Use absolute item-local millisecond keyframes with `hold` and `linear`.** Channels are uniquely identified, keyframe times strictly increase, and limits are 64 channels per item, 1,000 keyframes per channel, 4,096 path points, and 32 gradient stops. A channel's first/last values extend over uncovered time; exact timestamps choose exact values. Discrete topology uses hold. This isolates later marker/curve/loop semantics. Alternative: embed marker expressions or spring parameters immediately; rejected because #39–41 must define their resolution and bounds first.
5. **Keep edits transactional.** A `set_animation_channels` core operation replaces an item's collection. It uses the existing edit transaction, `expectedRevision`, lock checks, aliases, changed IDs, and undo/redo. Headless adds the corresponding tagged request and MCP registers `timeline_set_animation_channels` with standalone and batch schemas. Alternative: one operation per keyframe; rejected because partial multi-channel edits would be easy to publish.
6. **Migrate under the existing project lock.** Schema 22 adds empty channel defaults to schema-21 current state and every undo/redo snapshot, validates all candidates, then commits one recoverable generation. Older versions follow the existing deterministic migration chain. Any malformed or future document fails before publication. Rollback is recovery from the prior generation, not an in-place reverse migration; an older build must continue to reject schema 22.
7. **Keep ownership inside existing core modules.** Put serialized channel records in a `model` submodule and semantic validation in a `validation` submodule. Timeline edits call validation; scene evaluation consumes model types. Remove the standalone mixed-responsibility module. ADR 0003 and its architecture test must identify the nested owners and reject any unlisted top-level private module, avoiding a new owner cycle.
8. **Verify emitted media and stable worker tests.** The native render suite compares frame, range, draft, and export samples for position X/Y, independent scale X/Y, opacity, and static fallback; audio tests compare decoded output gain against base volume, mute, fades, and ducking at supported times and include the [-96, 12] acceptance boundaries. The render-parity CI job supplies FFmpeg and treats missing dependencies as a failure rather than a passing skip. Its exact command and required environment remain pinned by the CI policy validator and regression tests. The Windows worker-crash fixture waits for a completely readable PID record before opening the process handle; this changes test synchronization only.

## Contract, security, and failure behavior

`contracts/contract-ownership-v1.json` identifies governed consumers. Update canonical fixture/catalog entries, the headless request enum, bridge TypeScript union, MCP schemas and registration, capability level, and parity tests in one change. This is additive for clients. Core rejects wrong value tags, inactive channels, target mismatches, duplicate channel identity/timestamps, overflow, non-finite values, missing scoped references, and conflicts with legacy animation. No path, URI, SVG, network resource, or FFmpeg expression is represented in the channel payload. Missing item and stale revision retain existing stable error codes and retryability; invalid channel content is `INVALID_ARGUMENT`. No new private or remote data is introduced.

## Risks / Trade-offs

- [Catalog contains inactive names] → Capability reporting and docs distinguish active and reserved channels; write and reopen validation reject inactive payloads.
- [New channels conflict with legacy keyframes] → Core rejects overlapping effective properties, with fixture and transaction tests at both operation orders.
- [Schema migration changes history] → Exercise current, undo, redo, malformed snapshot, interrupted commit, future schema, and reopen cases.
- [Preview/export drift] → Compare evaluated values and rendered samples at exact and interpolated times across still, range, and export paths.
- [Inactive bounds would freeze later milestones] → Publish target and value metadata now with explicit deferred bounds; activation requires a later reviewed bound decision and evaluator.
- [Windows worker PID file creation races its reader] → Retry only transient sharing/not-found reads to a bounded deadline, then assert termination of the exact owned process.
- [Cross-language drift] → Consume canonical fixtures from Rust and TypeScript and run the governed contract check plus MCP integration.

## Migration Plan

First add schema-22 data and fixtures, then core validation/evaluation, then transport consumers and documentation. Run all affected tests and protected gates in the repository's required order. A failed migration leaves the prior generation intact. Existing simple projects migrate with empty channels and retain visual/audio output; older binaries reject the newer schema rather than downgrading it.

## Open Questions For Approval

The proposed first active subset is position X/Y, independent scale X/Y, opacity, and audio gain. Visual channels require the legacy transform representation, and audio gain uses decibels on top of existing media volume. The rest of issue #38's property families carry value tags and prospective targets but defer numeric bounds and remain unwritable until their owning renderer milestones. Approval of this amendment confirms that deferred-bound contract, model/validation ownership, output-level render evidence, and the test-only Windows worker PID-read repair.
