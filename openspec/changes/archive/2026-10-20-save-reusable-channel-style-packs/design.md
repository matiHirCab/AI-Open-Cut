## Decisions

### D1. Capture ordinary components instead of inventing recipe instructions

A pack stores closed native ComponentDefinition data plus recipe keys and native typed slot defaults. Capture recursively discovers the selected component closure, verifies bounded graph/native validity and copies only required font faces. Definitions receive fresh random UUIDs on instantiation. Track/item/marker identities are derived with SHA256 from the target component id, a distinct identity-kind tag and the portable source local id, using safe ASCII prefixes. This is fresh across projects and reproducible for an explicit reapply into the same definition; nested component references use the explicit recipe-to-target map. Native marker operations still validate/create the candidate; only the new private pack callback attaches these deterministic scoped marker ids and remaps corresponding changedIds before commit. No public operation identity override is introduced. Capture reads raw current-schema project JSON under the existing project lock, checks expectedRevision, then uses existing pure native validation and managed-font verification. It MUST NOT call prepare_project_data, load_project_data, recover_transaction or any migration/publishing helper. Reject pending transaction journals (including linked entries) with existing PROJECT_RECOVERY_FAILED, and reject legacy source schemas with VALIDATION_FAILED directing the caller to separately open/migrate first. No source staging is created. Drop the source lock before acquiring the root library lock. Supported legacy targets still use existing staged migration during explicit apply/reapply.

Alternative: a new recipe language or static core import of bridge JSON. Rejected because both duplicate domain behavior or reverse ownership. Existing canonical motif scenes serve test inputs only. Audio/global-resource dependencies are rejected explicitly in v1; managed image references are supported. Caption role is a recipe key plus a native text/rich-text slot id; text values and timeline timing remain ordinary native edits.

### D2. Closed portable package and fixed bounded library

New core-owned model/store modules use serde deny_unknown_fields, explicit identity uniqueness and existing project/native validators. FormatVersion=1 and componentSchemaVersion=46 are independent from pack version. Portable package contains name, recipes, font records with canonical base64 payloads, sanitized image dependency declarations, optional caption role and optional profile identity/version. It contains no filesystem paths, original source file names, origins, fontPath or fontFamily selectors. Capture retains font bindings and their exact face bytes; sanitize source-path diagnostics into an explicit generic capture warning. Validate imported font bytes and binding/profile identities with existing fonts::record/verify behavior, not a second parser. Arrays with explicit unique keys are preferred for package collections. Native slot maps retain special literal keys.

Limits: canonical portable package 8 MiB; 16 recipes; 1024 recursively counted items; 32 markers; 32 image dependencies; 32 font faces; all existing lower per-font/per-component/slot and graph limits remain. Bound raw import packageJson bytes before deserialize; use a core-only duplicate-aware JSON visitor with at most64 nested containers before typed deserialization so every repeated object key (including native slot maps/special literal keys) fails instead of BTreeMap last-write-wins; retain raw JSON through the CLI import path so serde sees duplicate/unknown fields. Validate native structure against an ephemeral project using sanitized dependency metadata for structure only; real apply always uses actual target assets and checks integrity.

Fixed channel-style-packs.json uses existing projects-root locking, bounded reads and atomic durable publication; 64 MiB, 16 latest-only records, UUID v4 and versions <= JavaScript MAX_SAFE_INTEGER, unique trimmed case-sensitive 1..80-scalar non-control names. get includes exact exportable package; import supplies an explicit new name and fresh identity/version1. No automatic rename or retry. Library updates cannot affect materialized projects. Alternative: pack directories/artwork copying/history generations; rejected for additional ownership and crash inventories. Already locked base64 0.22.1 becomes a direct core dependency; no new network/service dependency.

### D3. Explicit external dependencies

Font data is bundled and managed; artwork is a typed declaration of media kind, content hash, size and probe facts, without paths/origin. Caller supplies complete explicit target-project managed asset bindings; never auto-bind even a unique matching hash. Existing import_asset remains a separate explicit transaction. Binding validation yields DEPENDENCY_UNAVAILABLE when absent, ASSET_NOT_FOUND for absent target ids, INVALID_ARGUMENT for metadata mismatch, and existing integrity failures for corrupt content. Existing core rules govern permitted media and records.

Optional narration reference resolves through #207 at exact expectedVersion. Caller can explicitly replace it or disable it. Resolve outside project lock, return immutable resolved defaults/attribution for subsequent explicit provider workflow. No inference or readiness claim. Absent/stale reference blocks project effects. Alternative: bundle providers or silently snapshot unknown profiles; rejected to retain explicit #207 ownership/readiness.

### D4. One existing staged transaction for application

Refactor only the existing staged edit helper into a private callback-driven transaction primitive so ordinary edit/edit_batch behavior and validation frequency stay equivalent. Core-only callbacks prepare candidate edits/fonts and return existing AppliedBatch plus pack report metadata. No adapter callback or executable template is accepted. Existing prepare_project_data, preflight, font publish tracking, draft/history persistence, journal uncertainty and owned rollback remain the single transaction owner.

Instantiate uses existing ComponentCreate aliases for all seeds, ComponentUpdate for remapped populated recipes, MarkerCreate for captured markers and AddComponentInstance for caller placements. Maximum generated operations remains 100 (16 seeds +16 populate +32 markers +32 placements =96). Native limits may reject earlier. Reapply uses the same deterministic scoped local identities and retains the identity of unchanged markers. Identical definitions therefore yield unchanged digests while preserving native successful revision/undo semantics; genuinely changed locked tracks, including font-only changes, still fail. Reapply requires complete distinct recipe-to-existing-component mapping, uses existing ComponentUpdate lock/slot rules plus explicit MarkerDelete/MarkerCreate, and checks the same operation limit. It preserves instance overrides. Reject invalid/incomplete mapping before effects. Preserve native successful edit semantics, including one revision/undo even for equal definitions; report stable before/after semantic digests and changed status instead of inventing a no-op write contract.

ComponentUpdate's existing font-binding guard remains unchanged: strip input bindings for that operation, then attach only previously verified package bindings internally in the new callback and stage corresponding exact bytes/catalog before final native validation. No ambient lookup occurs for pack text. Before font preparation, every recursively reachable package text item must have its verified binding reattached; missing bindings fail rather than reaching ambient resolution. apply_edit_batch performs its existing matte-only batch check before this attachment. The new callback then invokes full existing candidate validation with verified font catalog before existing font preparation/preflight. Reuse an extracted native locked-track comparison helper from ComponentUpdate to compare ORIGINAL mapped definitions against FINAL rebound definitions, so postprocessing cannot bypass a font-only locked-track edit; slot lock checks remain within ComponentUpdate. Standard edits invoke that same extracted helper at their original point and retain original ordering. Stage candidate aliases and remapped ids, then validate with existing native functions. A stale expectedRevision wins before font writes. New managed assets are not fabricated from package metadata. Existing project media/history/drafts stay authoritative. Before journal publication rollback only owned staged resources; after uncertain journal publication existing recovery retains resources, with no effect retry. Root library lock is released before project lock; immutable package/profile snapshots prevent lock inversion.

Alternative: direct component replacement bypassing edits, or multi-commit recipe phases. Rejected for lock semantics and partial visible changes. Existing standard edit paths must retain their original checks, ordering and outputs; targeted before/after regression and fault tests are mandatory for shared-helper extraction.

## Risks / Trade-offs

- Font payloads may hit the 8 MiB package cap before existing per-font limits: return explicit bounded-package errors; no compression or implicit font subset.
- Whole-definition reapply intentionally changes definition defaults/markers: require explicit mapping/current revision and preserve per-instance overrides; show digest report.
- Capture cannot recover or migrate source data: explicitly reject pending journals/legacy sources, require a separate user-requested open/migrate, and prove all source bytes remain unchanged on success and failure.
- Shared persistence extraction can regress old edits: preserve unchanged transaction ownership/order and execute workspace/history/migration/fault suites.
- Narration reference resolution is separate from later generation: expose pinned resolved metadata, require existing bridge preflight for voice/provider readiness.
- Pending remote CI and external CODEOWNER review remain independent from local conformance; keep PR draft and state failures/pending checks explicitly.

## Migration Plan

No project schema bump or implicit migration. Existing core migration runs under its current project lock and shared resource transaction when an explicit pack mutation targets legacy data. Package schema46/future formats fail closed. Feature removal leaves applied content fully ordinary/editable/renderable; saved library is inert. Roll back code through normal review without deleting user library/project data. No deployment or merge is authorized.
