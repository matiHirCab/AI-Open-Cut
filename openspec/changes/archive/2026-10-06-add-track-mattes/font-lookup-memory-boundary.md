# Admitted lookup memory certificate boundary

This clarification resolves the meaning of "entire allocation contract" in glyph-memory-certification.md and the platform cursor allowances in font-lookup-platform-addendum.md. The unchanged 1 GiB request budget certifies application-requested and retained payloads and capacities; it is not a total process RSS, kernel, allocator implementation, or operating-system runtime heap bound.

Count all renderer-owned source/font payloads, vectors and maps including spare capacity and growth overlap, traversal frames and ancestor paths, returned paths, normalization and UTF16/name scratch, caller-owned directory records, and known native cursor data buffers. Linux glibc DIR data and Darwin ordinary cursor growth remain fully counted. Known content-sized retained data cannot be classified as opaque bookkeeping: Darwin MNT_UNION enumeration remains rejected before iterator creation. Every exposed or caller-owned buffer remains subject to pre-admission, and all existing font integrity, fail-closed resource handling, first-match ordering and normative limits remain unchanged.

Windows source qualification establishes bounds for the Rust-owned ReadDir/DirEntry records, shared roots, fixed WIN32_FIND_DATAW and derived conversion/path scratch. It does not establish a byte ceiling for closed-source FindFirstFile/FindNextFile internal handle implementation or runtime bookkeeping. Those OS-private internals are outside the application-owned certificate and must be disclosed as such; no claim of complete Windows DLL or process heap boundedness is authorized. This boundary does not exempt returned data, application-retained payloads, or any known content-sized cursor cache.

Required verification remains source-derived application-owner bounds, independent actual-capacity/allocator controls, before-iteration rejection, nested/first-match/cycle/failure tests and exact-head supported-platform CI. Local Linux evidence cannot be described as macOS or Windows runtime qualification. This clarifies the existing certificate rather than increasing a limit, weakening an oracle, adding a platform skip, or changing implementation behavior.
