## Context
Desktop has authoritative bounded hierarchy and compositing/narration inspectors and asynchronous revisioned edits. Preview is currently a placeholder. The baseline builds and renders under task-local Xvfb, Lavapipe and a DBus-enabled Xfwm window manager; initial missing-device and black-window attempts are not success evidence.

## Decisions
Retain existing Layer controls with unchanged selection and action semantics. Move cue scope/page/ID inspection into Cues and saved alignment, selected authored audio and bounded bus/master summaries into Audio. Tabs remain usable without item selection and clear hidden edit drafts through the existing reset/interaction-epoch mechanism. Reuse the same authoritative project and scoped selection.

Keep one frozen configured Renderer clone/cache per shell. Preview work executes outside GPUI rendering, guarded by the existing session admission/generation mechanism so edits/history/refresh cannot overlap within the shell. Ordinary window close is refused while work is active; the user can close again after completion. This avoids dropping a running native producer without inventing core cancellation semantics; forced process termination is outside the guarantee. Core.validate_revision owns stale-revision rejection, PathPolicy owns store/project confinement and Renderer owns frame/range validation and evaluation. Desktop parses only integer representation and passes typed existing PreviewReviewOptions/resolution/audio fields. Frame and range artifacts capture project ID/revision/options; project changes label retained reviews stale instead of rewriting their identity. Render failures expose core code/message/retryability and never publish a success artifact or mutate authoritative state. Latest frame/range metadata is bounded; disk artifacts follow existing core preview output behavior, with no new asset GC or retention contract.

Controls expose frame time, range start/end in project milliseconds, 540p/720p/project presets and audio inclusion; project fps remains explicit. Frame output appears as an image. Range output reports captured settings/warnings/relative path and offers Reveal MP4 through the native file manager only on user click; there is no embedded audio/video playback claim. No arbitrary path or network entry field exists.

## Verification
Automated tab/state/parsing tests and canonical core missing/stale/invalid paths; configured native frame/audio-video rendering with immutable revision and authoritative history/reopen checks; genuine GUI inspection/tab/edit/history/refresh/frame/range/failure interactions with screenshots and commands. Build, strict Clippy/full workspace and formatting required; unchanged bridge/provider checks may reuse verified #75/#73 evidence only with unchanged inputs. OpenSpec protected final gate required. No subjective quality claim or replacement of #70/#77 fixtures.
