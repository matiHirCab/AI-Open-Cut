## Context

Current schema is31; #49 changes rendering and adds its capability but does not change persisted schema. Existing VisualProperties own effects/crop/Transform2D and flatten into eligible items; existing update_item and atomic batches can replace an ordered vector without new operation names. VectorPath/Paint already provide closed typed geometry/color, and Transform2D already has canonical finite bounds. The active extended-effects limit is16, while fixture-only catalogs are not runtime authorities.

## Goals / Non-Goals

Store a full bounded typed mask description, expose/edit it transactionally and migrate every retained authoritative document. Keep all production rendering identical when metadata is authored. Alpha and luma must describe different possible coverage, not synonymous tags on unpainted geometry. Rendering, animation, source-layer dependencies and mattes remain later milestones.

## Decisions

### Closed painted path model

`Mask` is a strict object with exactly required `id`, `source`, `channel`, `operation`, `inverted`, `transform`, `featherPx`, `expansionPx`. `source` is exactly `{type:"path",path:VectorPath,paint:Paint}`. No optional subfields or implicit geometry/paint defaults are introduced. `channel` is `alpha|luma`; `operation` is `add|subtract|intersect|exclude`; inverted is boolean. IDs are nonempty strings of at most128 UTF-8 bytes, unique within the owning item's mask vector; the same ID on another item is independent. Unicode IDs remain ordinary identifiers, not resource locators.

Path uses canonical camelCase commands with object points, existing fillRule and strict object decoding, with duplicate-key tests at actual core/headless raw Serde boundaries only (MCP/Zod receives parsed objects and cannot detect lost wire duplicates), never fixture-only snake_case x/y commands. Required Paint includes solid, linearGradient and radialGradient. All existing path and paint validation applies, including command topology, coordinate bounds, finite color and stop ordering. No stroke is included. This is safer/smaller than layer sources: it introduces neither graph cycles nor missing source resources, and gradients yield spatially varying luma.

### Ownership and edits

Masks may be owned by visual media (image/video), text, solid_color, rectangle, shape, SVG and grid leaves in root or component tracks. Nonempty masks on groups, component instances, repeaters, captions, transitions and audio return nonretryable INVALID_ARGUMENT. Empty vectors are harmless defaults on every VisualProperties carrier. Existing component payload validation checks all local leaves, including hidden/unused definitions.

`update_item.masks` omission preserves; present array replaces verbatim in order; [] clears; null rejects. Creation operations continue creating empty masks; clients can create a leaf then update `@alias` in one batch. IDs are caller-authored, so no mask-specific creation alias is required. Existing root-item addressing is unchanged; component_create/component_update expose component-local masks through their typed item payloads. Existing drafts carry the same typed operation. Removing/reordering masks introduces no animation target constraints because mask animation is not activated. No new standalone edit or MCP tool is added.

### Coordinates and reserved coverage meaning

Transform is a required existing Transform2D value and uses its exact numeric bounds. Pixel positions refer to the owner's pre-effect, post-crop/clip local raster coordinate basis; normalized positions refer to that raster's width/height. Normalized anchor refers to the path's geometric bounds before paint/expansion/feather; degenerate/move-only paths have zero coverage. Transform opacity multiplies coverage once. Local transform order is existing anchor→scale→skew→rotation→position; mask transforms never alter owner transforms or ancestor opacity.

For later raster activation, alpha coverage is painted coverage alpha. Luma is `0.2126*R + 0.7152*G + 0.0722*B` for premultiplied linear RGB, equivalent to painted straight luminance multiplied by alpha. Transparent color contributes zero. Paint uses existing premultiplied linear-light gradient interpolation. Coverage is bounded 0…1. Inversion maps B to 1−B within the owner-local source raster domain; multiplying the owner source does not revive pixels removed by source crop/clip or extend source support. These are stored semantic definitions, not renderer implementation in #50.

Declared future processing order is path fill/paint→signed expansion→feather→mask affine transform and its opacity→inversion→ordered scalar combination, then multiply owner source premultiplied RGBA once before ordered effects. Positive expansion grows support; negative expansion contracts it. Feather is Gaussian sigma in local pixels with transparent extension/support ceil(3*sigma); zero is identity. Expansion's exact raster distance/sampling algorithm and cumulative pixel budget are intentionally #51 activation requirements: #50 does not claim pixel behavior for those parameters. No raw backend interpretation is permitted.

Let current coverage be A and next mask coverage B after inversion. Add=`A+B-A*B`, subtract=`A*(1-B)`, intersect=`A*B`, exclude=`A+B-2*A*B`. Seed is0 if first operation is add/exclude,1 if subtract/intersect; empty stack is identity 1. Thus one subtract yields a cutout and one intersect yields the mask. Only #51 implements these equations; tests in #50 verify exact ordered stored meaning and distinct alpha/luma paint examples.

### Explicit model complexity bounds

At most16 masks per item; at most 4096 masks per composition and 16384 per project. At most4096 commands per path (existing),65536 mask commands per composition,262144 per project. Existing Paint cap 64 gradient stops remains. Counts include hidden items, hidden tracks, every unused component once, and every source record before validation normalization; root plus every component count toward project totals. Repeated component instances do not duplicate stored model counts. Each current/history/draft candidate is validated independently under existing history/draft collection limits; no hidden content is omitted. Checked integer addition rejects overflow. Limits apply before publication; renderer budgets remain unaffected because metadata is not evaluated. Feather 0…128 and expansion −128…128 are finite inclusive local-pixel values. No raster allocation is required to validate metadata.

### Schema32 and migration

PROJECT_SCHEMA_VERSION becomes32. Source schemas1…31 reject any authored masks field (including []/null) in every root/component leaf before permissive defaults can erase it. These fields did not exist, so accepting injection would ambiguously reinterpret old documents. Source schemas32 omit masks→[] without forcing read-only rewrite; serializer omits empty vectors. Supported old schemas migrate through existing deterministic behavior to 32 with empty masks and unchanged IDs/revisions/provenance/assets/font bindings/timing. Unknown future/zero schema rejection keeps existing stable compatibility errors.

Use existing cloned current/history migration owner and existing locked crash-consistent store transaction. Validate all current, undo and redo snapshots and retained drafts before publishing any migration. Applicable version 2 draft bases are resolved against the matching retained revision; valid stale drafts keep revision-conflict behavior, and unavailable bases keep structural/catalog/resource validation without replay against unrelated current state. Premature masks in old-base draft operations reject before migration. Do not bump draft-envelope version merely for an additive operation field; preserve current version 2 semantics. An earlier-than 32 current-project source envelope rejects masks-bearing draft operations before migration, including drafts with unavailable bases; a schema 32 envelope keeps absent-base drafts structurally validated without replay. Do not infer a fictitious base or reject legacy-only stale drafts. Journal recovery remains prior to new migration; failure leaves authoritative project/history/draft bytes and all managed resources unchanged.

## Alternatives Considered

Unpainted paths cannot give meaningful luma differences and were rejected. Layer sources reuse existing visuals but require scoped source lookup, DAG/cycle/deletion/timing/visibility behavior overlapping #52 and were deferred. Managed mask images add asset ownership/decoding and were deferred. A raw SVG source or expression conflicts with safety policy. New set_masks/reorder_mask operations duplicate existing vector replacement. Activating rendering in #50 contradicts explicit dependency separation and output-preservation requirement. Reusing fixture-only max/IDs/types would incorrectly activate a placeholder contract.

## Risks / Trade-offs

Metadata edits create revisions despite unchanged output; capability/docs must say this clearly. New source kinds and animation targets can be additive later, but the meaning of existing fields/coordinates cannot silently change. Expansion raster behavior is not falsely promised before #51; that milestone must approve its sampling/bounds semantics while respecting stored local-pixel meaning. Tight aggregate limits make hidden invalid work fail early; boundary fixtures prove intentional inclusive behavior. Full Transform2D includes opacity, which must be documented and applied once in future implementation. Old-schema injection rejection must occur before nested defaults in all retained sources.
