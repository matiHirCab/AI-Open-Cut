## Risks / Trade-offs

- Caller transcript/provenance may be inaccurate → label it explicitly supplied/approved, retain exact evidence, never claim factual verification or media transcription correctness.
- Timing boundaries can remove negation/context → retain adjacent context/full segment evidence and prominent review/cut warnings; deterministic grouping is not a semantic quality score.
- Project can change during reads → compare captured identity/revision/digest after planning and fail stale results. No side effects need replay/recovery.
- Large data or repeated chunk identifiers → strict closed schema, bounded bytes/counts/text/times and explicit rejection, not truncation.
- Shared ownership/projection integration can conflict with future #208 → record touched central files and preserve semantic union in eventual integration; no device/WIP retrieval and no speech/narration implementation changes.

## Closed interface and limits

Version1 input: projectId, assetId, expectedRevision, approvedTranscript=true, chunks, targetDurationMs, maxCandidates and optional selection/edits. IDs are nonempty at most128 UTF-16 code units; source IDs are unique per chunk/segment. Chunks (1..128) have id, offsetMs, durationMs, providerId, modelId, maxDurationMs and segments. Segments (total1..4096) have id, startMs, endMs, text(1..2000) and optional words(total<=32768, word1..256). Chunk/segment/word times are nonnegative safe integers, positive duration, contained, ordered nonoverlapping; each word stays inside its segment. No invented word timing or forced text normalization. Full chunk coverage is contiguous from0 to resolved source duration, even when selection explicitly requests only a planning subinterval. Optional selection has exact source start/end and must fit the source; output records both full source duration and selected scope so omitted content is explicit. Candidate edits must stay within selected scope. Target duration is1000..180000ms, maxCandidates1..32; reject excess groups instead of truncating and suggest selecting a smaller explicit interval. Edits (0..32) name unique existing candidate IDs and optional start/end (both required together) and hook/cta/rationale (each0..1000); reject unknown IDs or no-evidence intervals. Candidate ID is candidate-1..N in deterministic source order. Source duration<=86400000ms. Input byte cap4194304; successful output cap8388608 with explicit limit error, not partial JSON. CLI error output contains version1, a closed planning kind and optional existing core code/retryability, fixed bounded message and no resolved path. No new stable core error identifiers are added.

Plan output records version1, source project/asset/revision/digest/duration/transcript approval and supplied provenance, selected scope/target, candidates and explicit warnings. Each candidate includes source start/end/duration, full quote evidence with chunk/segment original identity/ranges/text and fullyIncluded flag, bounded immediate before/after context, supplied editorial fields and warnings. Always label semantic context as requiring review and supplied editorial assertions as unsupported claims requiring review; do not infer that temporal completeness proves semantic completeness. Exact canonical positive/negative fixture examples own closed field shapes; tests must compare them with actual emitted/parsed structures rather than generate fixtures from implementation.

### Exact shape and independent grouping oracle

All objects below are closed. Optional means omitted, not null, except explicit context nulls. Word = {word:string,startMs:number,endMs:number}. Segment = {id,startMs,endMs,text,words?:Word[]}; Chunk = {id,offsetMs,durationMs,providerId,modelId,maxDurationMs,segments:Segment[]}. Input = {version:1,projectId,assetId,expectedRevision,approvedTranscript:true,chunks:Chunk[],targetDurationMs,maxCandidates,selection?:{startMs,endMs},edits?:{candidateId,startMs?:number,endMs?:number,hook?:string,cta?:string,rationale?:string}[]}. Chunk IDs are unique across input and segment IDs unique within their chunk. Empty transcript/chunks/segments are rejected. Existing core-resolved contentHash must be non-null {algorithm:'sha256',digest:64 lowercase hexadecimal digits}; otherwise fail kind=source rather than invent an identity.

Success = {version:1,ok:true,source:{projectId,assetId,revision,contentHash,durationMs,transcriptApproved:true,transcriptionProvenance:'supplied',chunks:{id,offsetMs,durationMs,providerId,modelId,maxDurationMs}[]},selection:{startMs,endMs},targetDurationMs,candidates:Candidate[]}. Candidate = {id,startMs,endMs,durationMs,evidence:Evidence[],context:{before:Evidence|null,after:Evidence|null},editorial:{hook:string,cta:string,rationale:string},warnings:Warning[]}. Evidence = {chunkId,segmentId,startMs,endMs,text,fullyIncluded:boolean,words?:Word[]}; its ranges/optional word times are absolute original source times. Editorial defaults to empty strings. Warning is exactly context_review | editorial_claim_review | cut_boundary | context_excluded | duration_mismatch | chunk_boundary | candidate_overlap, with unique entries in this order. Every candidate has context_review. Any nonempty editorial field adds editorial_claim_review. Any partially included evidence adds cut_boundary. Any immediate neighboring source segment or partial evidence adds context_excluded. Duration outside inclusive80%-120% of target adds duration_mismatch. Intersection with multiple chunk intervals adds chunk_boundary. Strict positive overlap with any other candidate adds candidate_overlap symmetrically. None of these warnings claims to detect all semantic/claim failures.

Error = {version:1,ok:false,error:{kind,message}} where kind is input | limit | source | stale | internal, OR {version:1,ok:false,error:{kind:'core',message,code:string,retryable:boolean}} preserving the existing core code/retryability. Planning messages are fixed bounded strings; unexpected exceptions have a generic internal message. Errors go to stderr and nonzero exit, success only to stdout. Successful JSON is fully serialized and checked against8MiB before any stdout write; invalid UTF-8/JSON/input>4MiB fails without successful output. EPIPE/output errors terminate unsuccessfully without retrying or emitting another success.

Grouping oracle: flatten original segments in source order; take those with positive overlap with the explicit/default selection. Accumulate consecutive complete segments until min(last.end,selection.end)-max(first.start,selection.start)>=target, then start the next group. Keep the final shorter group with the duration warning when outside80%-120%. Group edges are intersected with selection, never extended outside it. A selection cutting a segment is accepted only as an explicit cut: retain its entire original quote/range/words, mark fullyIncluded=false and add cut_boundary/context_excluded. Apply any human edit after grouping, within selection, require positive duration and at least one intersected original segment, and rebuild evidence/context/warnings from the immutable transcript. Do not regroup after edits or silently adjust supplied edit boundaries. If initial group count exceeds maxCandidates fail limit, with no truncated successful plan.

Canonical example fixed before schema/service: source duration2000, chunks c1 offset0/duration1000 and c2 offset1000/duration1000, each with one segment s1 local0..1000, texts respectively 'I do not recommend that.' and 'The result is uncertain.'. Target1000/maxCandidates2 yields candidate-1 source0..1000 and candidate-2 source1000..2000, exact quotes, reciprocal neighboring context and context_review/context_excluded warnings. Edit candidate-1 to250..1250 with hook 'Guaranteed success' retains both complete quotes with fullyIncluded=false, adds editorial_claim_review/cut_boundary/context_excluded/chunk_boundary/candidate_overlap; candidate-2 also receives candidate_overlap. A selection250..1750 at target1000 creates one group250..1750 with both full quotes, cut/context/duration/chunk warnings. Gap at second chunk offset1001, declared limit999 for duration1000, future version2, unknown fields, unapproved transcript, source revision mismatch and requested maxCandidates1 for two groups are independently authored negative fixtures. Tests must consume these authored expectations rather than deriving them from the planner.
