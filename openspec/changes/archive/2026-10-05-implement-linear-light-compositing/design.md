## Context

MG-M4-01 (#49) closes a gap left by the evaluated-scene and stacking foundations (#13/#19). `render_artifact/extended_visual.rs` already owns a bounded f32 linear-premultiplied local raster, crop, effects, inverse affine sampling and shutter averaging. It serializes each layer separately to straight 8-bit sRGB; `render_plan.rs` then overlays those layers and ordinary FFmpeg-rendered sources in encoded space. Correcting only effect inputs would leave final scene composition wrong. No current model contains authored masks/mattes/non-normal blends; four effects and crop already exist.

## Goals / Non-Goals

**Goals:** One explicit current pipeline for every supported source and intent; analytic linear/alpha correctness; deterministic clocks/geometry; canonical preflight; bounded streamed composition; intact read-only render lifecycle and typed errors.

**Non-Goals:** See proposal: no new authored/public/persisted fields, HDR/profile management, new graphics paint algorithms, masks/mattes/blends, or output-color controls. Existing decoded local RGBA is the source boundary. Source-local SVG clip/fill/stroke and shaped-text paint obey their existing contracts; the compositor cannot recover color precision already quantized by a source rasterizer.

## Decisions

1. Extend the existing sampled raster adapter into a full-scene streaming compositor. Each requested output time samples every evaluated visual through the existing source/crop/effect/transform functions, keeps working rasters linear-premultiplied, averages temporal samples, and blends bottom-to-top into an opaque black f32 canvas. Serialize only the completed scene to existing PAM/lossless stream preparation; pass one opaque sampled video resource to FFmpeg, preserving its audio graph, muxing and encoders. Keep renderer-neutral evaluated facts separate from process-local file bindings. Alternatives: adding sRGB↔linear conversion around current 8-bit overlays loses precision and still leaves affine interpolation gamma-encoded; FFmpeg float filtering would require a new audited float alpha/resampling implementation. Reuse current Rust primitives for an independently testable deterministic path.
2. Resolve ordinary visuals through the same sampled semantics as effect-bearing visuals. Finalize missing intrinsic sizes and source rasters before composition; preserve legacy anchors, Caption box placement, media orientation/time mapping, shaped text and instance clocks. Source initialization may be cached within existing resource/cache limits, but output frames and complete sequences are never retained. Plain text source paths that previously used drawtext must have a complete local raster source rather than being silently discarded. No special gamma fast path is allowed; optimizations must prove equivalent linear results.
3. Make the eight normative stages explicit, with identity masks/mattes and normal source-over until their separate model milestones exist. Existing crop remaps into the established destination extent rather than introducing a new geometric clip contract. Existing effect support/origin/anchor and transition semantics are unchanged. Apply inherited opacity/transition gain once to all RGBA components after transforms.
4. Extend owning-layer sample certification to all participating visuals and count destination visits including shutter samples, enforcing the specified per-output-frame budget (including shutter samples) with checked arithmetic. Certify the conservative peak of simultaneous f32 canvas/source/transform/average/effect buffers and decoded/encoded RGBA bytes before allocation, with a 1GiB ceiling and 64MiB reservation for the existing shared raster cache. Process uncached source rasters one layer at a time; do not retain unbounded decoded sources. Count 16 bytes per working RGBA pixel and 4 bytes per boundary RGBA pixel plus bounded overhead. Use existing 16M-pixel source/output and effect work limits; certify hidden/retained authored data under existing validation. Validate requested sampled facts before any output collision inspection or render workspace/process. Runtime decode/process failure uses established cleanup and stable errors, not partial output.
5. Keep authored and persisted declarations unchanged: no schema bump or migration. Add `linear_light_compositing_v1` to protocol-v1 capability reporting only when the complete renderer is ready; no claim on an unavailable backend. Synchronize the single canonical capability catalogs in `contracts/headless-protocol-v1.json` and `contracts/mcp-surface-v1.json`, the Rust reporter, bridge typed capability declarations, and parity evidence according to `contract-ownership-v1.json` and ADR 0002. Prepare designated CODEOWNER review evidence for the parent-created draft PR; maintainer approval remains pending and is separate from delegated specification approval, independent agent review and automated gates. Existing `evaluated_scene_rendering` does not distinguish older encoded composition and is insufficient for this detection. The unique additive name keeps existing clients valid. Render outputs change for translucent intersections and resampling by design. Update the complete affected legacy-preservation specification and review goldens against independent color formulas, never weaken tolerances.

## Risks / Trade-offs

- [CPU/source decode cost grows for ordinary visuals] → Stream frames, reuse valid source resources within existing cache bounds, and measure representative native checks; keep strict limits and failures explicit.
- [Legacy source geometry/text placement differs under sampler] → Cover each source family, plain and transformed text/Caption, media orientation, fractional origins, parent/component clocks and legacy keyframes using existing regression suites and focused production tests.
- [Golden drift hides a bug] → Assert independent approximately-188 white/black half-alpha output, analytic multi-layer source-over, transparent-edge resampling and stage-order cases before deliberate golden update.
- [Preflight and materialization disagree] → Share evaluated sampling/certification functions and instrument no-side-effect failures; verify decode/process failures clean workspaces.
- [Cloud native prerequisites unavailable] → Report blockers; do not skip required tests or weaken gates. Activation and tool logs live outside the repository.

## Fractional native-clock certification amendment (2026-10-05, approval pending)

The accepted Java-safe whole sourceInMs envelope is wider than absolute f64 fractional timestamp precision. Preserve authored validity, but fail closed at render preflight when an active video sample's mapped local clock contains a fractional millisecond and cannot be converted safely. A shared source-time helper computes the mapped local clock, compensated TwoSum residual for sourceInMs + local, direct seconds-conversion residual (using fused multiplication), and conservative native-seconds comparison rounding precision. The sum of absolute residuals plus the native comparison precision must be <=1e-6ms (1ns); nonfinite or excess returns nonretryable INVALID_ARGUMENT before workspace/output creation or decode/raster side effects. Materialization calls the same helper defensively. Image samples stay zero. Exact whole-millisecond local clocks bypass this fractional-only certification and keep prior backend compatibility/errors. No authored/persisted/API/schema restriction or silent approximation is introduced. Test Java-safe largeoffset+.25 rejection, partial quantization, ordinary .1/.25 fractions, nested/sourceIn native fixtures, whole-clock compatibility and unchanged project/history.
