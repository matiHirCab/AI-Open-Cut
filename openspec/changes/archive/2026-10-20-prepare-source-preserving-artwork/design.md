## Decisions
- Pure decode/transform/encode belongs in assets/artwork, using pinned png 0.18.1 (Rust), sha2 and existing errors. Store/artwork coordinates existing core paths, locks and persistence. No new private owner edge or renderer. Alternative FFmpeg decode from assets would violate owner boundaries.
- Supported preparation inputs require managed Image probe width/height matching decoded dimensions; legacy assets missing those facts remain otherwise usable and require explicit reimport through the existing allowed import before this new operation. Missing facts are not proof of damaged bytes. Existing first-open migration may normalize legacy state before preparation; preview introduces no artwork mutation and byte-preserving preview claims apply to current normalized state. Source PNG bytes <=4 MiB, decoded dimensions 1..512 per side and <=262144 pixels; output preserves dimensions plus radius padding. Reject unsupported non-PNG/APNG/invalid input before publication with UNSUPPORTED_MEDIA or VALIDATION_FAILED. Decoder must cap allocation before decode; no animation, automatic orientation, scaling or ambient profiles. Normalize using PNG EXPAND | STRIP_16: expand palettes, tRNS and sub8 grayscale, retain the high byte of16-bit channels, replicate grayscale RGB and add alpha255 where absent; ignore gamma/ICC metadata (no color-management claim). Reject APNG acTL and unsupported normalized output explicitly. Inspect alpha only after normalization.
- Params: optional cleanup {color:[r,g,b],tolerance:0..255}; outline {radius:0..16,color:[r,g,b,a]}. All channels integers 0..255; default cleanup none, radius0. Clear alpha of matching four-connected border-reachable pixels only, using max per-channel absolute RGB difference <= tolerance. Ignore transparent pixels for color matching but allow flood traversal across them. RGB under alpha0 is immaterial. Fully enclosed opaque matching subjects remain. Cleaning never claims correct subject segmentation.
- Pad all sides by radius and record content offset [radius,radius]. Outline uses separable square/Chebyshev dilation of cleaned alpha. Multiply dilated alpha by selected outline alpha with nearest-integer division by255, then composite original above outline in straight RGBA with explicitly rounded integer source-over. For nonnegative integers round(n/d)=floor((n+floor(d/2))/d). With s=source alpha and o=round(dilatedAlpha*outlineAlpha/255), D=s*255+o*(255-s), output alpha=round(D/255); each RGB channel=round((sourceChannel*s*255+outlineChannel*o*(255-s))/D) when D>0. Transparent output RGB is zero. Efficient two-pass max avoids unbounded radius-squared work; max loop work is bounded by dimensions/radius. Mask shows cleaned (pre-outline) alpha with padding as opaque grayscale RGBA [alpha,alpha,alpha,255]. Light/dark PNGs flatten the canonical rounded result over opaque [255,255,255]/[32,32,32] using round((channel*alpha+background*(255-alpha))/255). Radius0 adds no outline. All outputs same padded dimensions. Exact small RGBA fixtures independently verify arithmetic.
- Core prepare request {projectId,expectedRevision,sourceAssetId,parameters} validates current revision/integrity and managed Image type, then returns manifest {version:1,projectId,expectedRevision,sourceAssetId,sourceHash,parameters,resultHash,reviewHashes:{result,mask,light,dark},width,height,sourceWidth,sourceHeight,contentOffset} and four PNG payloads result/mask/light/dark in base64; aggregate encoded bytes <=8MiB. Hashes are canonical sha256 hex over the exact encoded PNG bytes; resultHash equals reviewHashes.result. Core recomputes and compares all four reviewHashes on commit, and CLI verifies every named review file before apply. Core commit accepts only manifest and recomputes canonical bytes, comparing source and result hashes and dimensions under the project lock. This is typed caller intent, not an authorization token. Commit creates a new asset only; source/timeline unchanged; usual single revision/history semantics. A stale manifest fails REVISION_CONFLICT; same-revision mismatch or malformed parameters fails VALIDATION_FAILED; corrupt managed bytes use ASSET_INTEGRITY_FAILED. No silent retry/rebase/recompute acceptance.
- Asset optional artworkDerivation contains version1, sourceAssetId, sourceHash, parameters, source dimensions and contentOffset. Source must resolve to a managed Image in same snapshot with matching hash; reject self/cyclic/dangling chains and inconsistent dimensions/offset with ASSET_INTEGRITY_FAILED. Canonical asset reference owner adds derivation sources; deletion uses existing ASSET_IN_USE; drafts retaining a derivative transitively retain its source. History already retains complete snapshot catalogs. No parallel collector. New generated image does not use speech origin.
- Schema47 gates derivation fields and migrates current plus retained history from every supported old version under existing lock. Older snapshots gain no fabricated derivations; future versions fail closed. Derivation field omitted for old assets. Old builds reject schema47; migration is forward-only; preserve backup for downgrade. Owner211 confirms no competing project schema bump: its package v1 pins componentSchemaVersion46. Integration must retain that format marker independently of project47, explicitly convert supported old component payloads, and preserve all eight combined new operations. A package path unable to encode transitive artwork source provenance must reject new derived artwork explicitly until an approved extension is delivered; never strip provenance or rewrite old packages. Package interoperability is not claimed verified on this branch, which does not contain211.
- Core stays platform-neutral. CLI file-package backend initially supports Linux only: hold parent/package directory descriptors opened O_DIRECTORY|O_NOFOLLOW, use /proc/self/fd anchored child operations and reject changed captured parent identity. Regular file opens add O_NONBLOCK before fstat to reject FIFO/device inputs without blocking. Other platforms fail DEPENDENCY_UNAVAILABLE before core dispatch or file mutation until a safe native backend is delivered. A hostile same-user can replace final regular files between checks; hashes validate selected package content, not originating-process ownership.
- Thin headless prepare/commit operations; bridge CLI `artwork-preview`, `artwork-apply`, `artwork-discard` (or equivalent subcommands) uses existing runtime config/path restrictions and only typed core calls. Preview writes one new explicit output directory, bounded four named PNG files and manifest, through owned staging; refuse existing destination and symlinks. Apply requires explicit approval flag, reads bounded strict manifest and verifies review-file hashes before sending typed commit. Discard removes only exact owned package files after ownership/symlink checks; foreign files cause refusal and remain intact. No auto retention/GC outside project-managed state; review packages are explicit user-owned output, max8MiB each and one per invocation. Documentation gives inspection/open commands and discard guidance.
- Cancellation before commit cannot change project state; process termination during compute leaves no project commit; commit boundary uses existing durable transaction and no false rollback claim. Partial preview staging is owned cleanup only. Apply crash uncertainty requires inspecting project revision/asset provenance before retry; no automatic replay. Repeated preparation from original is deterministic; repeated commit at captured revision conflicts.
- Public changes are additive new operations/CLI, optional Asset metadata and MCP project-state output subtree only. Preserve tool count, old schemas, request aliases, errors/retryability. Update canonical catalogs, ownership/CODEOWNERS and exact inverse proofs rather than recapturing historical baselines. The artwork fixture also owns existing CLI preview/apply/discard JSON request fields, explicit approve:true, and strict version1 success/failure wrappers through valid/invalid examples consumed by the actual exported unchanged parser and response schema; actual runtime outputs must satisfy the same governed envelopes. Required CODEOWNER review remains separate from independent specification approval.

## Risks / Trade-offs
PNG-only excludes ordinary JPEGs; explicit errors/documentation. Simple cleanup can remove border-connected subjects; review light/dark/mask and discard before commit. Padding changes image dimensions; explicit metadata/documentation, no automatic timeline resize. File packages can be edited; compare file/manifest hashes, core revalidates bytes and revision. Large public asset schema touches shared catalogs; precise additive proof and independent review are mandatory.

## Verification backend distinction
The default checked-in artwork acceptance command MUST continue to require genuine FFmpeg/FFprobe and retain every original independent pixel, source/hash, commit/history and process-lifecycle assertion. Source smoke intentionally runs without media-tool dependencies and SHALL invoke an explicit `--hermetic` verification mode instead. That mode uses a generated probe stub accepting only the exact synthetic original PNG and an independent Python-standard-library PNG decoder with CRC, zlib and filter0..4 handling for normalized RGBA8 outputs. It SHALL execute the same literal result/mask/light/dark oracles and CLI/core/history/cancellation/oversize assertions without skips. Reports MUST identify the selected verification backend; hermetic evidence does not establish FFmpeg/FFprobe or installed renderer readiness. This test-only amendment does not change production behavior, required native gates, tool installation or CI workflows.
