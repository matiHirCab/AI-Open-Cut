Core owns assets, validation and staged complete-generation migration. No active OpenSpec changes existed at discovery.

## Goals / Non-Goals

Persist optional alignment faithfully through existing speech workflows and adopt schema38 atomically. Preserve unaligned results and rendered output. Non-goals are those in proposal.md, especially #61 inference and #62 markers.

## Decisions

1. Add optional `alignment` to `SpeechGeneration`, omitted when absent, rather than inventing estimated data for legacy speech. `SpeechAlignment` is a closed record with required `sentences`, `words`, `phonemes`, `quality`, `providerId`, and required nullable `modelId`/`modelVersion`; omission is a closed-shape error while explicit null is accepted. Explicit null `alignment` is rejected; omission is the only absent form. Quality is exactly `native`, `forced`, or `estimated`. Distinct arrays preserve independent provider capabilities. No confidence score is inferred.
2. Timed text uses closed `{text,startMs,endMs}` records with safe JSON integer (0 through 9007199254740991), asset-relative millisecond offsets and positive spans. Each granularity is ordered and non-overlapping; gaps are allowed. Cross-granularity nesting is not required. At least one array must be nonempty. Combined segment count is at most 100000, each text is nonblank and at most4096 UTF-8 bytes, total timing text at most1 MiB; provider/model identifiers at most256 UTF-8 bytes. Every end must be within the generated asset's known positive duration. This avoids floats/NaN and unbounded processing. Existing `VALIDATION_FAILED` is the semantic failure; malformed closed wire shape uses existing `INVALID_ARGUMENT` handling.
3. Alignment provider/model metadata records the alignment producer independently of synthesis metadata. Native providers can repeat synthesis identity; forced/estimated producers must report their own identity. No paths or source asset IDs are introduced, so centralized #82 ownership is unchanged.
4. Use existing project-locked staged generation migration and journal, not a second persistence mechanism. Current generated-speech mutations load/migrate eagerly before target checks; move their request/adoption flow to existing `prepare_project_data`, tracked uncommitted resources, prepared fonts/draft updates and the same journal durability/warning boundary. New tracked generated-content admission stays in the assets owner. Reject intrinsic/contextual invalid alignment before source admission or project adoption; target/revision/resource failures preserve current/history/draft/managed-file bytes, including genuine legacy inputs. Preserve success IDs, revisions, undo/redo, shared-content ownership and recovery warnings. Buffer raw asset object entries with existing BufferedValue before presence guards and typed replay, retaining duplicate-field rejection. Genuine schema37 sources migrate with absent alignment; raw pre38 speech generation rejects presence of `alignment` including null before defaults. Validate every retained snapshot before publication, retain old source guards, and reject future versions. Draft envelope/operation contracts remain unchanged because generated speech commits are not timeline batch-edit operations; document that acceptance item as inapplicable.
5. Carry optional alignment on bridge `SynthesizedSpeech` into existing commit/replace provenance without claiming capabilities or changing worker-v1 synthesis. Clone new nested alignment on provider-result receipt inside the existing cleanup boundary using its strict structural schema; later provider mutation cannot change a retained artifact. Malformed provider shape uses existing TTS_INVALID_OUTPUT; ordering/UTF8/aggregate/duration semantics remain core-owned. The existing Kokoro worker metadata parser/protocol remains unchanged. Canonical `speech-alignment-v1.json` owns new fields/bounds/scenarios and registers core, bridge, headless and MCP consumers. Existing project/protocol/MCP owners synchronize the additive field and schema markers manually. Every predecessor projection must strip only approved alignment/version additions and prove exact pinned predecessor semantics; do not regenerate the MCP catalog from runtime registrations.
