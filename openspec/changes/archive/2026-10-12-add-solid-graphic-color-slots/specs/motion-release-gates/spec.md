## MODIFIED Requirements

### Requirement: Complete supported-platform default native scene proof
Native release checks MUST execute the unchanged complete #77 ten-group recipe, shared-card overrides and synthetic cue witnesses on Linux, Windows and macOS. Default-core release rendering MUST be proved separately from private source/compiled MCP cache instrumentation and the #78 default-package workload. Actual frame, repeated cached frame, audio-bearing range, export, undo/redo and fresh reopen SHALL consume canonical semantics with retained SSIM>=0.99/floatPCM RMS<=0.0001/one-frame tolerances, real stream metadata and independent witness controls. Default cache evidence SHALL observe current owned native process identities and arguments across same-PID exec, rather than cached pre-exec names/arguments, and direct native process invocations and immutable artifact content without fabricating media or changing production behavior. Existing cache-eligible ELF/PE builds MUST demonstrate warm final-encoder reuse; the existing Mach-O identity bypass MUST be recorded as an uncached deterministic fallback, rather than altering production support or disguising a forwarding wrapper. The source/compiled MCP fixture SHALL retain its exact original ELF/PE cache counters and enforce exact zero-hit/zero-miss, one-through-six final-execution counters on existing Mach-O bypass, preserving all scene/media witnesses and deadlines.

#### Scenario: R3 Render the complete default scene and restore it
- **WHEN** the configured default-core workload and existing source/compiled MCP fixture run on a supported platform
- **THEN** all ten groups and literal cue/override/output witnesses remain exact, native media/cache/lifecycle evidence passes and each build's instrumentation status is explicit

#### Scenario: R4 Fail closed on native or fixture gaps
- **WHEN** tools/font/media are absent, configuration is partial, a fixture/witness is incomplete or altered, or actual required native cases/report are absent or skipped
- **THEN** acceptance fails with preserved authoritative state/resources and no smaller sample, synthetic result or mislabeled binary substitutes for complete native proof

#### Scenario: R12 Observe an owned native command across exec
- **WHEN** an owned Unix child is observed before and after same-PID executable/argument replacement
- **THEN** passive collection identifies the current native-looking collector control and its final-command arguments, settles the owned child, preserves all original native cache assertions and never claims the control as rendered evidence


### Requirement: Mandatory release orchestration preserves prior acceptance
A separate pinned release matrix MUST require Windows, macOS and Linux canonical cases and complete native execution, actual dependency/font provenance, strict reports and nonempty evidence artifacts at the published head. Missing/changed platforms/pins/commands, default/instrumented substitutions, skipped cases, golden mutation or failure masking SHALL be rejected by automated policy controls. Drivers SHALL terminate and settle only owned process trees on timeout/error. Existing protected workflows, assertions/deadlines, unrelated public/provider contracts, approved project schema45 adoption with supported schema44 predecessors and protocol1 and source fixtures MUST remain unchanged. Completion SHALL require local conformance/archive/protected gates plus terminal exact-head native and prior required CI, with failed/blocked checks disclosed.

#### Scenario: R9 Complete every platform at the published head
- **WHEN** the release matrix and prior required workflows execute the published implementation
- **THEN** genuine all-platform canonical/default/MCP proof, strict reports and actual artifacts are terminal successful before advancing #80

#### Scenario: R10 Reject weakened orchestration
- **WHEN** a platform/pin/native command/report/feature identity is changed, a failure is masked or golden mutation is enabled
- **THEN** policy/required-execution tests reject the change while prior protected gates remain enforced

#### Scenario: R11 Bound owned driver failure cleanup
- **WHEN** a driver-owned process and actual descendant hang or fail
- **THEN** the existing finite driver control terminates and settles that owned tree, preserves diagnostics and returns failure without affecting unrelated work
