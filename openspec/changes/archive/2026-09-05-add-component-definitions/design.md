## Context

Issue #22 follows schema-10 groups. ADR 0004 retains Project.tracks as root and places reusable definitions beside it. The fixture-only catalog supplies maximum component depth 16 and definition count 512. Issues #23 and #24 own slots and evaluated instances respectively.

## Goals / Non-Goals

Implement reusable persisted timelines, full graph validation and atomic typed definition management. Exclude root instance placement, rendering, slots and arbitrary nested edit paths.

## Decisions

1. Schema 11 adds required `components: []` to Project. Definitions contain `id`, `name`, `width`, `height`, `durationMs`, and `tracks`. Reuse existing track and ordinary item shapes, with a closed `component_instance` item for nested definitions only. It carries common visual/order/parent properties, `id`, `componentId`, `startMs`, `trimStartMs`, `durationMs`, and `timeScale`; no slots, paths or expressions. Definition dimensions follow existing project dimension limits. Existing root item lookup remains root-only. Alternatives: reusing schema 8 would corrupt version meaning; duplicating entire nested definitions per instance would defeat reuse.
2. Explicit positive integer-millisecond duration owns the component interval. Every local item fits within it using checked ends. All newly introduced times must be JavaScript-safe integers. Nested source end `trimStartMs + durationMs * timeScale` must be finite and at most the referenced duration; timeScale must be finite and positive. Invalid mappings fail rather than clamp, loop or silently truncate. Empty definitions with positive duration are valid. Top-left coordinates and flat ordering are local to each definition; root duration ignores unused definitions. Automatic duration inference was rejected because cycles and updates would otherwise create implicit propagation semantics.
3. Definition IDs are project-unique; track/item IDs are unique inside their owning composition. Parent scope must equal `component:<definitionId>` for component children and remain `root` for root children. Resolve parents and transition endpoints only inside that composition. Nested instances are visual overlay items that can have static transforms and group parents; instance transition endpoints and legacy animation are deferred. Validate all definitions, even unreachable/hidden ones. Collect identity before indexing and derive dependency edges from actual nested items, never a client-supplied edge list. Repeated instances of the same definition are valid. Reject missing definitions before bounded DAG traversal; cycles fail, and longest dependency path permits 16 edges, with a leaf at depth zero. Apply at most 512 definitions, 4096 total stored component items and 4096 total component tracks, plus existing per-composition item/graph/keyframe/media limits. No recursive expansion is needed.
4. Add `component_create {name,width,height,durationMs,tracks}`, `component_update {componentId,name,width,height,durationMs,tracks}` and `component_delete {componentId}`. Create assigns a new definition ID; update is a full definition replacement retaining ID. All fields above are required. Track/item IDs in supplied local tracks are explicit stable identifiers, not generated aliases. The only resultAlias producer is create. Resolve componentId and nested component references from earlier creation aliases in batches; do not reinterpret local track/item IDs as aliases. Validate after each ordered operation against the evolving candidate. A referenced definition cannot be deleted. Updates cannot alter/remove an existing locked local track; adding/removing/reordering other tracks retains locked-track relative order. Delete fails if any local track is locked. Root locks do not independently block definition edits. Full replacement avoids introducing a new edit-scope parameter across the entire API.
5. Core validation owns semantics and is reused for load, current/history migration, drafts, mutation and direct rendering validation. Timeline owns operations; assets owns references across root, every definition, retained history and durable drafts. No component media can be garbage-collected while retained anywhere. Preserve media provenance and validate existing font/resource confinement without adding new resource inputs. Keep ownership imports inside ADR 0003; any necessary new edge requires an explicit ADR/test update before coding that edge.
6. Headless and bridge add closed typed operation variants, project response fields and capability `component_definitions`. MCP uses matching standalone tools and existing batch wrapper; domain errors remain core-owned. Component IDs missing from target or references use ITEM_NOT_FOUND; malformed definitions, cycles, bounds and referenced deletion use INVALID_ARGUMENT; locks use TRACK_LOCKED; stale revisions remain retryable REVISION_CONFLICT. Existing envelope/batch-limit errors are unchanged. Mutation results report the affected definition ID; child IDs are composition-local and are not flattened into ambiguous root changedIds. No protocol-major or error-catalog change is needed.

## Risks / Trade-offs

- Stored instances are not rendered yet: reject instance items in root explicitly and advertise only definition support; definitions do not add output to root previews/exports.
- Whole-timeline replacement can remove local edits: optimistic revisions and lock checks preserve concurrency; undo restores the exact definition.
- Reused local IDs can confuse root scans: audit all project traversal sites, media retention, draft operations and test cross-scope collisions.
- Multiplying bounded collections can still be expensive: bound aggregate stored component tracks/items before indexing or traversal; check DAG depth without expansion.

## Migration Plan

Extend the existing supported migration chain to initialize an empty components collection for schemas 1–10, including retained snapshots. Validate the entire envelope under lock before atomic publication or managed-asset writes. Schema-11 documents must contain components; schema zero and future versions retain stable rejection. Preserve root values, revision, media and rendered output. Recovery must select one whole pre/post generation. No downgrade is provided; undo reverses definition mutations within schema 11 rather than restoring a historical schema version.

## Approval decisions

Approval includes schema 11, explicit durations, definition-only nested instances, full-replacement editing, composition-local identity and the specified limits. These are concrete proposed choices filling the roadmap issue's underspecified details; no implementation begins before approval.

## Review correction design

Component validation additionally checks all nested millisecond fields against 9007199254740991, including keyframes, media fades, caption generation and source word times. Generation timestamps remain positive; do not add keyframe-within-item or fade-within-duration limits. Only media items accept volume keyframes.

Caption source provider/model IDs must be nonblank and at most 128 UTF-8 bytes, language nonblank, optional model version nonempty, original text nonblank and at most 4096 UTF-8 bytes, and words nonblank. Optional source/word confidence must be finite in [0,1]. Word start/end must be safe integers with start < end. Source words remain original provenance, independent of current caption placement; no current-interval containment or rewriting. Caption bottom margin is at most 4320. Empty word arrays and omitted optional confidence remain valid.

Use component-scoped checks in the existing validation owner and INVALID_ARGUMENT; preserve missing-reference and revision handling. Canonical fixtures explicitly distinguish Rust decoding, MCP structural acceptance, and core semantic acceptance. Verify both creation and full replacement, batch rollback, current/history fail-closed reads, drafts, direct rendering and actual MCP source/packaged workflows.
