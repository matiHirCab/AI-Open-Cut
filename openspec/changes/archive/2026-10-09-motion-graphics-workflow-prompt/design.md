## Context
All dependency operations are merged; MCP owns reusable workflow guidance. Domain validation stays in core.

## Decisions
Register a unique additive prompt and its existing Zod string schema pattern. Use published operation names and describe alias-based typed operations rather than duplicate executable domain rules. Serialize caller arguments as JSON in the guidance. Do not invoke headless, providers or mutate state during retrieval. Keep prior prompt names and canonical predecessor pins intact using an explicit successor rollback, never repin history.

## Workflow
Inspect status/capabilities, project state/revision/tracks/canvas and available assets. Plan project-coordinate visuals and integer-millisecond timing using closed schemas. Define/instantiate components with slots and markers in a single batch when dependent creations need aliases. Apply only supported presets; resolve missing references and limitations before commit. On stale revision refresh/replan; on failed batch inspect unchanged state. Review audio-enabled preview range artifact and immutable revision before approved export with explicit overwrite policy. Verify undo/redo and project reopen after meaningful changes.

## Risks and Verification
Guidance does not execute or guarantee creative quality. Test discovery, schema, content/tool-name accuracy, literal argument framing, deterministic retrieval and no side effects, invalid missing/empty/non-string inputs over actual source and packaged MCP. Preserve existing workflow suites covering domain failures/history/reopen and native preview/render semantics. Run full bridge, contract and protected specification gates; reuse unaffected Rust/Python/native evidence only when inputs are unchanged. CODEOWNER review remains a draft PR review obligation.
