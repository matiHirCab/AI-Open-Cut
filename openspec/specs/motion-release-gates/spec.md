# Motion release gates

## Purpose

Require complete canonical and native release evidence with honest scoped observations and preserved prior acceptance.

## Requirements

### Requirement: Closed canonical security and stress release cases
The release suite SHALL require exactly depth, SVG, repeater, particle, render-plan, preview, memory and timing areas through actual authoritative positive/boundary/negative assertions. It MUST retain existing core finite/complexity/path and typed error semantics, atomic rollback, optimistic revisions, history/reopen and shared resource ownership. Missing, duplicate, zero-test, ignored/skipped or failed required execution MUST block acceptance. A verification inventory MUST NOT introduce transport-side domain rules, change production limits or replace existing independent fixtures.

#### Scenario: R1 Execute all canonical limit areas
- **WHEN** the release gate executes a healthy closed case inventory
- **THEN** actual tests prove all eight existing limits and their intended success/refusal paths, with complete passing execution evidence

#### Scenario: R2 Refuse incomplete or invalid release cases
- **WHEN** an area/test is missing, duplicated, ignored, skipped, not selected or fails, or invalid/unsafe/missing/stale input is exercised
- **THEN** release acceptance fails while existing domain failure/rollback/history/resource semantics remain authoritative

### Requirement: Complete supported-platform default native scene proof
Native release checks MUST execute the unchanged complete #77 ten-group recipe, shared-card overrides and synthetic cue witnesses on Linux, Windows and macOS. Default-core release rendering MUST be proved separately from private source/compiled MCP cache instrumentation and the #78 default-package workload. Actual frame, repeated cached frame, audio-bearing range, export, undo/redo and fresh reopen SHALL consume canonical semantics with retained SSIM>=0.99/floatPCM RMS<=0.0001/one-frame tolerances, real stream metadata and independent witness controls. Default cache evidence SHALL observe direct native process invocations and immutable artifact content without fabricating media or changing production behavior. Existing cache-eligible ELF/PE builds MUST demonstrate warm final-encoder reuse; the existing Mach-O identity bypass MUST be recorded as an uncached deterministic fallback, rather than altering production support or disguising a forwarding wrapper. The source/compiled MCP fixture SHALL retain its exact original ELF/PE cache counters and enforce exact zero-hit/zero-miss, one-through-six final-execution counters on existing Mach-O bypass, preserving all scene/media witnesses and deadlines.

#### Scenario: R3 Render the complete default scene and restore it
- **WHEN** the configured default-core workload and existing source/compiled MCP fixture run on a supported platform
- **THEN** all ten groups and literal cue/override/output witnesses remain exact, native media/cache/lifecycle evidence passes and each build's instrumentation status is explicit

#### Scenario: R4 Fail closed on native or fixture gaps
- **WHEN** tools/font/media are absent, configuration is partial, a fixture/witness is incomplete or altered, or actual required native cases/report are absent or skipped
- **THEN** acceptance fails with preserved authoritative state/resources and no smaller sample, synthetic result or mislabeled binary substitutes for complete native proof

### Requirement: Scoped measured release workload envelope
The private default-core six-second192x10810fps release workload MUST discard one warm-up and collect exactly3 direct measured captures, with explicit whole-capture monotonic elapsed time and maximum sampled resident bytes of the isolated owned test process tree including native descendants at declared5ms intervals. Reports SHALL preserve complete fixture/font/tool/platform/architecture/build and execution identity, sample counts/units/scope/aggregation and actual collector lifecycle. Every measured capture on Linux x86_64 MUST have elapsed<=600000ms and sampled RSS<=2147483648bytes, inclusive; other platforms SHALL report their actual observations without treating those numerical bounds as universal promises. The #15 schema3/stage-definition2 baseline MUST remain report-only and unchanged; unlike environments or non-additive stages MUST NOT be compared or combined as like-for-like costs.

#### Scenario: R5 Capture and validate actual observations
- **WHEN** the isolated native workload completes one warm-up and3 measured captures
- **THEN** genuine finite observations and complete identity pass strict private validation, native descendants are included and sampler/process resources settle

#### Scenario: R6 Enforce inclusive scoped bounds
- **WHEN** a correctly identified Linux x86_64 release capture is at an envelope boundary or one unit above it
- **THEN** equality is accepted and elapsed/RSS excess refuses release acceptance without changing an existing production or baseline threshold

#### Scenario: R7 Reject false or malformed observations
- **WHEN** report version/shape/count/number/identity/build/sampler data is unknown, absent, duplicated, inconsistent or not actual required execution
- **THEN** strict validation refuses publication/acceptance and mutated validator controls are not claimed as native measurements

#### Scenario: R8 Observe and settle an owned memory child
- **WHEN** an actual owned child allocation is observed or readiness/observation/timeout fails
- **THEN** the collector proves descendant sampling and reliably stops/joins while owned child termination settles without accepting incomplete measurements

### Requirement: Mandatory release orchestration preserves prior acceptance
A separate pinned release matrix MUST require Windows, macOS and Linux canonical cases and complete native execution, actual dependency/font provenance, strict reports and nonempty evidence artifacts at the published head. Missing/changed platforms/pins/commands, default/instrumented substitutions, skipped cases, golden mutation or failure masking SHALL be rejected by automated policy controls. Drivers SHALL terminate and settle only owned process trees on timeout/error. Existing protected workflows, assertions/deadlines, public/provider contracts, schema44/protocol1 and source fixtures MUST remain unchanged. Completion SHALL require local conformance/archive/protected gates plus terminal exact-head native and prior required CI, with failed/blocked checks disclosed.

#### Scenario: R9 Complete every platform at the published head
- **WHEN** the release matrix and prior required workflows execute the published implementation
- **THEN** genuine all-platform canonical/default/MCP proof, strict reports and actual artifacts are terminal successful before advancing #80

#### Scenario: R10 Reject weakened orchestration
- **WHEN** a platform/pin/native command/report/feature identity is changed, a failure is masked or golden mutation is enabled
- **THEN** policy/required-execution tests reject the change while prior protected gates remain enforced

#### Scenario: R11 Bound owned driver failure cleanup
- **WHEN** a driver-owned process and actual descendant hang or fail
- **THEN** the existing finite driver control terminates and settles that owned tree, preserves diagnostics and returns failure without affecting unrelated work
