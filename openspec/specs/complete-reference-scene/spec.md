# Complete Reference Scene Specification

## Purpose

Define the complete editable ten-capability fixture, authoritative lifecycle and genuine audiovisual evidence through existing APIs.

## Requirements

### Requirement: Complete editable ten-group reference recipe
The suite MUST provide a versioned bounded local recipe authored from an empty project through existing typed APIs that demonstrates all ten groups: nested reusable compositions/typed slots; vector graphics including moving diagonal grid/decorative shapes/repeater; rich layered outlined typography; versioned impact/staggered entrances/looping scan or radar animation; masks/mattes/blend/ordered effects/particles; explicit tracks/z/stable stacking; atomic construction with creation aliases; six synthetic narration-generated marker timings; designed semantic audio events/buses/ducking/DSP/normalization/analysis; and cached audiovisual preview/export. It MUST include at least three instances of one shared rule-card definition with distinct overrides and preserve parent/component scoped identity. The recipe MUST record independently declared timing/settings/source provenance and an exact ten-group witness map. Existing #70/#58 and other frozen independent references MUST remain unchanged.

#### Scenario: F1 Build the complete scene
- **WHEN** the reference recipe is constructed in a fresh store through standalone or atomic typed operations
- **THEN** independent authored witnesses cover every group, aliases resolve in order and the shared definition, overrides, markers and audio routes remain exact

#### Scenario: F2 Detect incomplete capability coverage
- **WHEN** a capability witness, required operation, distinct slot override or cue/audio binding is removed or changed
- **THEN** independent recipe/state coverage checks fail rather than accepting a visually attractive incomplete sample

### Requirement: Reference scene authoritative lifecycle
The scene MUST work through real source and compiled MCP clients without public DTO changes. Invalid input, missing references, stale revisions and later batch failures MUST preserve existing error code/retryability and authoritative files/history/resources. Duplicate-with-overrides, parent edits, undo/redo and fresh reopen MUST preserve exact content and scoped identities while checking revision/update-time bookkeeping separately. Existing schema44 and predecessor migration behavior MUST remain unchanged; no migration SHALL be invented for test-only data.

#### Scenario: F3 Reject and restore reference edits
- **WHEN** existing operations construct, duplicate or modify the scene, or fail invalid/missing/stale/late, followed by undo/redo and reopen
- **THEN** complete expected state/history/resource evidence and original error semantics agree across core and actual source/compiled MCP

### Requirement: Genuine reference audiovisual evidence
Configured native reference checks MUST use actual FFmpeg/FFprobe and a fixed font, demonstrate visible frame output and audio-bearing540p/720p range review with repeated revision-keyed cache reuse, final export and fresh reopened/history states. Equivalent requested settings MUST share canonical evaluated semantics and retain SSIM>=0.99, aligned float-PCM RMS<=0.0001 and one-frame timing tolerances. Literal structural/timing/output witnesses and negative controls MUST supplement cross-intent comparisons; the latter MUST NOT be presented as an independent newly generated full-frame golden. Analysis MUST report actual LUFS/true peak through existing core behavior. Required missing tools/font/media checks MUST block acceptance, while unexecuted supported-platform checks remain explicit limits pending their own issues.

#### Scenario: F4 Compare native review and export
- **WHEN** the full scene is rendered and cached through frame/range/export at matched settings, then reopened or restored through history
- **THEN** stream and sampled decoded output evidence meets retained tolerances, cached artifacts keep immutable identity and independent witness expectations remain true

#### Scenario: F5 Fail closed on missing or drifting evidence
- **WHEN** native dependencies are missing or an independent witness/timing/output negative control is altered
- **THEN** the required check fails and no optional skip or cross-intent agreement substitutes for genuine complete-scene evidence
